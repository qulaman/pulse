# CLAUDE.md — WAG Pulse

Инструкции для Claude Code. Прочти этот файл полностью перед любой задачей. Детали по слоям: `docs/FRONTEND.md`, `docs/BACKEND.md`, `docs/DATABASE.md`. Общая концепция продукта: `docs/CONCEPT.md`.

## Что это за проект

Внутренняя платформа компании West Arlan Group (~40–50 сотрудников, Казахстан):
директор голосом раздаёт задачи/объявления/очки → Whisper + Claude парсят → сотрудники получают карточки в PWA → отчитываются → дашборд «Пульс» и ТВ-экран показывают всё в реальном времени. Плюс рейтинг очков и магазин мерча.

## Стек (не менять без обсуждения)

- **Next.js 15+ (App Router), TypeScript strict, Tailwind, Framer Motion, Recharts**
- **Supabase**: Postgres + RLS, Auth, Realtime, Storage, Edge Functions, pg_cron
- **PWA**: next-pwa / serwist, Web Push (VAPID)
- **AI**: OpenAI Whisper API (STT, ru), Claude API `claude-haiku-4-5` (парсинг, structured JSON, tool use)
- **Fallback-уведомления**: Telegram-бот (grammY)
- Деплой: Vercel

## Незыблемые принципы

1. **Ценность = количество убранных действий.** Основной вход директора — голос ИЛИ свободный текст одной строкой (на встрече); оба идут в один парсер. Любая функция директора — голосом, текстом или одним тапом/свайпом. Каждая новая фича проходит фильтр: «добавляет ли она хоть один тап к основному флоу?» — если да, переделать или не выпускать. Насмотренность директора ≠ желание сложности: глубина только вторым слоем по явному тапу.
1a. **Game feel обязателен, но никогда не блокирует действие.** Данные пишутся мгновенно, эффекты играют поверх через `<EffectsLayer>`. Каталог и правила — docs/FRONTEND.md, раздел Game Feel. Тестировать на бюджетном Android.
2. **У сотрудника максимум 3 кнопки** на карточке задачи: Принял / Уточнить / Не могу.
3. **Задачу закрывает только директор** (pending_review → done | rework).
4. **Баланс очков = SUM(point_transactions)**. Никогда не хранить и не мутировать баланс как поле. Append-only.
5. **Аудио директора всегда сохраняется** рядом с транскриптом и доступно сотруднику.
6. **Мультитенантность с первого дня**: `company_id` во всех таблицах, RLS на каждую таблицу. Пока компания одна, но схема — SaaS-ready.
7. Язык интерфейса — русский. Комментарии в коде — английский.
8. Мобильный-first. Отдельный роут `/tv` — только чтение, ноль интеракций.

## Структура репозитория

```
/app                    # Next.js App Router
  /(director)/pulse     # дашборд Пульс
  /(director)/confirm   # экран подтверждения распознанного голосового
  /(employee)/feed      # лента личного канала
  /(employee)/tasks     # «Мои дела»
  /ether                # Эфир (общая лента + рейтинг)
  /shop                 # магазин
  /tv                   # ТВ-режим (kiosk)
  /api                  # route handlers (voice, push, parse, tv-control...)
/components
/lib                    # supabase client, ai clients, matchers, utils
/supabase
  /migrations           # SQL-миграции (единственный источник правды по схеме)
  /functions            # Edge Functions
/docs                   # FRONTEND.md, BACKEND.md, DATABASE.md
/tasks                  # рабочие приказы для агентов (одна задача = одна сессия)
/tracker                # index.html — трекер «план/факт» по 12 неделям
```

## Статусы задач (enum, не расширять без причины)

`sent → accepted → in_progress(опц.) → pending_review → done | rework(→ снова accepted)` + `declined` (сотрудник «Не могу», требует причину).

## Правила работы

- Любое изменение схемы БД — только через новую миграцию в `/supabase/migrations`, никаких правок старых миграций.
- Перед реализацией фичи проверь соответствующий docs/*.md — там контракты и схемы.
- Секреты только в env: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `VAPID_*`, `TELEGRAM_BOT_TOKEN`. Service role — только на сервере, никогда в клиенте.
- RLS-политики обязательны для каждой новой таблицы в той же миграции, где создаётся таблица.
- Пиши тесты на критичную логику: парсер сущностей (фикстуры реальных фраз на русском), матчинг имён, транзакции очков, заморозка очков в магазине.
- Все времена в БД — timestamptz UTC; отображение — Asia/Aqtobe (UTC+5).
- Коммиты мелкие, по фиче; conventional commits.

## Очерёдность разработки (следовать ей)

1. **MVP**: миграции ядра → auth+роли → личный канал → голосовой конвейер (одна задача) → экран подтверждения → push → Пульс (блоки 1–3) → приёмка.
2. Эфир + мульти-сущности из одного голосового + голосовые вопросы (tool use).
3. Очки + реакции + рейтинг + свайп-приёмка.
4. Магазин + ТВ-режим + пульт ТВ + повторяющиеся задачи + отложенная отправка.
5. TTS-сводки, делегирование, умные напоминания, режим планёрки.

## Definition of Done для фичи

- Работает на телефоне (эмуляция iPhone SE и среднего Android) — проверено визуально.
- RLS проверена: сотрудник не видит чужие задачи (написан негативный тест).
- Realtime-обновления не требуют перезагрузки страницы.
- Ошибки сети/AI-API обработаны: у пользователя всегда понятное состояние, голосовое не теряется (retry с сохранённым аудио).
