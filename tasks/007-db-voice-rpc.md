## Шаги
1. Миграция `20260910100000_voice_pipeline.sql`:
   (а) таблицы ровно по DATABASE.md: `ingest_batches` (unique `(company_id, client_request_id)`), `ai_logs` (все поля; `status text not null`), `inbox_items` (+ `moddatetime` на `updated_at`), `announcements`, `announcement_acks`, `reminders`, `recurrence_rules`; затем `alter table tasks add constraint tasks_recurrence_rule_fk foreign key (recurrence_rule_id) references recurrence_rules`;
   (б) индексы из раздела «Индексы» для этих таблиц (`ai_logs (company_id, created_at)`, `announcements (company_id, created_at desc)`, `recurrence_rules (next_run_at) where is_active`, `reminders (remind_at) where not sent`, unique на `client_request_id`) плюс `ai_logs (company_id, client_request_id, kind)` — по нему confirm находит строку parse;
   (в) RLS по матрице: `announcements`/`acks` — select компания (кроме `tv`), insert announcements — director, ack — свой (`user_id = auth.uid()`); `notification`-таблиц нет; `ingest_batches`, `ai_logs` — select director, insert/update — нет политик (service role и security definer); `inbox_items` — select director или автор (`user_id = auth.uid()`), insert/update — автор, пока `status <> 'confirmed'`; `reminders` — свои (`user_id`); `recurrence_rules` — select компания, write — director. Каждая таблица: `enable row level security`;
   (г) Storage: `insert into storage.buckets (id, name, public) values ('voice','voice',false) on conflict do nothing`; политики на `storage.objects` для bucket `voice`: insert — `auth.uid()::text = (storage.foldername(name))[2]` и `(storage.foldername(name))[1] = auth_company_id()::text` (путь `{company_id}/{owner_id}/{uuid}.ext`); select — владелец по тому же условию (чтение чужого — только signed URL с сервера); update/delete — нет.
2. Функция `confirm_voice_batch(payload jsonb, client_request_id uuid, p_now timestamptz default now()) returns jsonb`, `security definer`, `set search_path = public`:
   - роль вызывающего: `auth_role() = 'director'` иначе `raise exception 'forbidden' using errcode='P0001'`; `v_company := auth_company_id()`, `v_user := auth.uid()`;
   - идемпотентность: `insert into ingest_batches (company_id, user_id, client_request_id, result) values (…, '{}') on conflict (company_id, client_request_id) do nothing`; если вставки не было (`not found`) — вернуть сохранённый `result` с `duplicate: true`;
   - `payload`: `{ source, audio_path?, transcript, parsed_entities: [...], confirmed_entities: [...], was_edited: bool, edit_fields: text[], force_now?: bool, inbox_id?: uuid }`. Обрабатываются только `confirmed_entities`;
   - тихие часы (D-38): окно из `companies.settings->'delivery_window'` (`{"from":"08:00","to":"21:00"}`, дефолт при отсутствии), зона `Asia/Aqtobe`; `v_quiet := p_now at time zone 'Asia/Aqtobe'` вне окна; при `v_quiet and not force_now` — задачи получают `status='scheduled'`, `scheduled_send_at` = ближайшие `from` (сегодня, если ещё впереди, иначе завтра) в Asia/Aqtobe → timestamptz;
   - для каждой сущности по `kind`: `task` — insert в `tasks` (`author_id = v_user`, `assignee_id = entity.assignee_id` — обязателен, иначе exception `assignee_required`; `group_id` — если в сущности строка, то один и тот же uuid на все сущности с этим же `group_id` внутри батча (map строка→`gen_random_uuid()`); `deadline = (deadline_iso)::timestamptz` (в UTC автоматически по смещению), `priority`, `source`, `source_audio_path = payload.audio_path`, `source_transcript = payload.transcript`; если у сущности есть собственный `scheduled_send_at` — `status='scheduled'` с ним; иначе — правило тихих часов; иначе `sent`); `delegation` — как task на исполнителя с `body = note`; `announcement` — insert `announcements (author_id, audio_path, transcript = text)`; `reminder` — insert `reminders (user_id = v_user, text, remind_at)`; `recurrence` — insert `recurrence_rules (author_id, assignee_id, title, body null, priority 'normal', rrule, is_active true, next_run_at = p_now)`; `points` и `query` — пропустить, добавив в `skipped` с причиной (`points_disabled` / `query_not_persisted`);
   - `ai_logs`: `update ai_logs set confirmed_entities = payload.confirmed_entities, was_edited = payload.was_edited, edit_fields = payload.edit_fields where company_id = v_company and client_request_id = client_request_id and kind = 'parse'`; `inbox_items`: если передан `inbox_id` — `status='confirmed'`;
   - `result := { task_ids[], announcement_ids[], reminder_ids[], recurrence_ids[], skipped: [{kind, reason}], scheduled: bool }`; `update ingest_batches set result = result …`; вернуть `result || {duplicate: false}`.
3. Миграция `20260910100100_task_rpc.sql`:
   (а) `task_status_guard()` — `create or replace` с добавленной веткой `old.status = 'declined' and new.status = 'sent'` → `ok := uid is null or urole = 'director'` (G.20 «Настоять»); при этом переходе `closed_at := null`;
   (б) `transition_task(task_id uuid, to_status task_status, payload jsonb default '{}', client_request_id uuid default null) returns jsonb`, `security definer`: если `client_request_id` не null — идемпотентность через `ingest_batches` как в п.2 (дубль → сохранённый result); затем `update tasks set status = to_status where id = task_id and company_id = auth_company_id()` — RLS не действует внутри security definer, поэтому права переходов проверяет `trg_task_status_guard` по `auth.uid()`/`auth_role()` (они доступны внутри функции); `not found` → exception `task_not_found`; исключение `invalid_transition` из триггера пробрасывается как есть; после update — сообщение в `task_messages` при наличии `payload->>'reason'` (declined: `type='text'`, `content = reason`, `meta = {"decline_reason": true}`) или `payload->>'comment'` (rework: `type='text'`, `content`, `meta = {"rework_comment": true}`); `result := {task_id, status}`;
   (в) `revoke_task(task_id uuid, client_request_id uuid default null) returns jsonb`, `security definer`: только director (`auth_role()`); задача в `scheduled` — `delete` (никому не доставлена, D-01), иначе `update … set status = 'revoked'` (триггер проверит терминальность); идемпотентность через `ingest_batches`; `result := {task_id, action: 'deleted'|'revoked'}`;
   (г) `grant execute` на три функции роли `authenticated`; `revoke` от `anon`.
4. `supabase/seed.sql` — дополнить: `companies.settings = '{"delivery_window":{"from":"08:00","to":"21:00"}}'`; одно объявление с одним ack; одна строка `ai_logs` (`kind='parse'`, `client_request_id = '40000000-0000-0000-0000-000000000001'`, `parsed_entities = '[]'`) — для теста confirm; одна `inbox_items` в `parsed`.
