## 1. Правила для всех фаз

1. **Смысл решений не меняется.** Разрешено: пометить статус, свести цепочку в сводку, убрать из спеки историю, исправить факт по коду. Всё, что требует выбора, — вопрос в отчёт.
2. **Метки построенности** у разделов и пунктов спек, где это не очевидно: `[есть]`, `[за флагом: settings.<ключ>]`, `[не построено]`. План без метки читается как контракт — именно это и сбивало агентов.
3. **История из спек удаляется, а не переносится:** датированные вставки «(владелец, 2026-09-1x)», «Сделано …», зачёркнутый текст, замеры смоуков, описания найденных багов — всё это уже есть в WORKLOG и в DECISIONS. В спеке остаётся правило и ссылка на решение.
4. **Факт — по коду, не по памяти и не по доку.** Каждое «есть»/«нет» проверять grep'ом по `app/`, `components/`, `lib/`, `supabase/migrations/`, `package.json`.
5. **Рабочая копия.** Каждая фаза — своя папка и ветка: `git worktree add Z:\Pulse-018<x> -b docs/018<x>-<слаг> main`. Фазы только про тексты: `node_modules` и pnpm не нужны, **pnpm не вызывать вообще**. Коммит — с проверкой ветки (`test "$(git branch --show-current)" = docs/018<x>-<слаг> && git commit …`), `git add` только по путям скоупа. Перед отчётом `git merge main` в свою ветку: конфликты в DECISIONS/WORKLOG/FRONTEND/DESIGN — чужие дописывания, сохранить обе стороны. В main — только по слову владельца.
6. **Номер решения** (если фаза его заводит) — последний в `git show main:DECISIONS.md` плюс один, прямо перед записью: параллельные сессии дважды брали один номер.
