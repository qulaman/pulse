## Шаги
1. Установить `@anthropic-ai/sdk` (последняя версия) и `tsx` (dev). Модель парсера — `claude-haiku-4-5` (env `PARSER_MODEL`), эскалации — `claude-sonnet-5` (env `PARSER_ESCALATION_MODEL`). Параметр `thinking` НЕ передавать (Haiku 4.5 — без adaptive thinking; на эскалации тоже не включать). `max_tokens: 4096`.
2. `lib/ai/prompt.ts` — `buildSystemBlocks(roster: RosterUser[])`: массив текстовых блоков system: [0] статичный текст промпта — **дословно** AI.md §2 (все 13 правил, таблица конвенций), с `{ROSTER_JSON}` вынесенным в отдельный блок [1] = JSON ростера, отсортированного по `id`, поля `{id, full_name, aliases, position?}` (только активные). На блок [1] — `cache_control: { type: "ephemeral" }`. Никаких дат/времени в system. `buildUserMessage({ transcript, source, now })` — шаблон AI.md §2: `Сейчас: {weekdayRu}, {formatAqtobe} (+05:00). Источник: {source}.\n<input>\n{transcript}\n</input>` (транскрипт вставляется как есть; теги `<input>` внутри транскрипта экранировать заменой `<` на `‹`).
3. `lib/ai/examples.ts` — `FEW_SHOT: { user: string; assistant: ParseResult }[]` — восемь пар П1–П8 из AI.md §4 с ПОЛНЫМИ объектами по схеме (каждое поле каждой сущности), имена и id отображены на `tests/stt/roster.json` по таблице из §4 (Айгуль → u-005, Ерлан → u-001 и в тексте реплик «Ерлану Б.», Марат → u-003, Сакен → u-004); контекст всех примеров — `Сейчас: четверг, 13.08.2026 16:32 (+05:00). Источник: voice.` Даты в примерах — как в доке (после правки: пятница = 14.08, понедельник = 17.08). Функция `fewShotMessages()` → `MessageParam[]` (user/assistant попеременно; assistant-контент — JSON-строка), на ПОСЛЕДНЕМ assistant-сообщении `cache_control: { type: "ephemeral" }`. Тест `lib/ai/examples.test.ts`: каждый `assistant` проходит `ParseResultSchema.parse`; все `assignee_id` в примерах существуют в `tests/stt/roster.json`; П8 содержит две task с одинаковым `group_id`.
4. `lib/ai/parse.ts` — `parseTranscript(input: { transcript: string; source: 'voice'|'typed'|'shared'; now: Date; roster: RosterUser[]; model?: string; client?: Anthropic }): Promise<ParseOutcome>`, где `ParseOutcome = { entities: Entity[]; model: string; escalated: boolean; usage: { input_tokens; output_tokens; cache_read_input_tokens; cache_creation_input_tokens }; latencyMs: number; raw: unknown }`. Вызов — `client.messages.parse` с `output_config: { format: zodOutputFormat(ParseResultSchema) }` (`zodOutputFormat` из `@anthropic-ai/sdk/helpers/zod`), `system` = блоки из п.2, `messages` = few-shot + user-сообщение. Клиент: `new Anthropic({ timeout: 20_000, maxRetries: 2 })` по умолчанию. Обработка: `stop_reason === 'refusal'` → `ParseError('parse_refused')`; `stop_reason === 'max_tokens'` → один повтор с `max_tokens × 2`, затем `ParseError('parse_failed')`; `parsed_output === null` → `ParseError('parse_failed')`; сетевые/5xx после ретраев SDK → `ParseError('parse_failed')` с `cause`. **Эскалация (AI.md §8):** если транскрипт > 400 символов ИЛИ сущностей > 3 ИЛИ любое `assignee_confidence`/`deadline_confidence` (не null) < 0.6 → повторный вызов с `PARSER_ESCALATION_MODEL`, результат его, `escalated: true`; параметр `escalate?: boolean` (default true) — evals гоняют и с ним, и без. `class ParseError extends Error { code: 'parse_refused' | 'parse_failed' }`.
5. `lib/ai/postprocess.ts` — `postprocess(entities: Entity[], roster: RosterUser[], source): PostprocessedEntity[]` — семантическая валидация AI.md §3: `assignee_id`, которого нет в ростере или неактивен → `null` (далее matchName); `points` с `amount === 0` → удалить; `points` с `amount < 0` при `source === 'voice'|'typed'` → пометить `blocked: 'points_blocked'` (не удалять — /confirm покажет причину); `points` при `source === 'shared'` → `blocked: 'points_blocked'`; невалидный ISO в `deadline_iso`/`remind_at_iso`/`scheduled_send_at` → `null` + `confidence` null. Каждой сущности с полями исполнителя добавить `assignee: AssigneeMatch` (из `matchName`). Тип `PostprocessedEntity = Entity & { assignee?: AssigneeMatch; blocked?: 'points_blocked' | 'assignee_unmatched' }` (`assignee_unmatched` — при `assignee.status !== 'matched'` у task/points). Тест `lib/ai/postprocess.test.ts` на 5 кейсов выше.
6. `tests/ai/parser_evals.jsonl` — по строке на кейс, формат TESTING.md §4: `{"id","source","transcript","frozen_now","expected":{"entities":[...]}}`; в `expected.entities` каждая сущность — `kind` + проверяемые поля: `assignee_id` (строка или `null` — `null` значит «ОБЯЗАН быть null/не matched»), `deadline_iso` (строка → сравнение в пределах 30 мин; `null` → обязан быть null; поле отсутствует → не проверяется), `amount`, `group_with` (id другой ожидаемой сущности, с которой должен совпадать `group_id`). Наполнить **32 кейса**, `frozen_now` везде `2026-08-13T10:00:00+05:00` (четверг), кроме few-shot (16:32 того же дня):
   - `fs-01…fs-08` — тексты П1–П8 (ожидания = их assistant-ответы, сведённые к проверяемым полям);
   - `a-001…a-015` — фразы корпуса категории A (`tests/stt/corpus.jsonl` id 001–015): `kind: task`, `assignee_id` из `names[].user_id`, `deadline_iso` — вычислить по таблице конвенций D-15 от `frozen_now` (например «к завтрашнему обеду» = 14.08 13:00; «к пятнице» = 14.08 09:00); фразы вне таблицы (например «до конца дня») — поле `deadline_iso` НЕ указывать, ничего не выдумывать;
   - `f-047…f-050` — категория F: ровно одна сущность `kind: query`;
   - регрессии из живых прогонов 2026-08-20: `r-016-mini` transcript `"Закази мы доверение. Пятницу общее собрание в 9, Марат готовил зал, Айгуль вызовет повестку, и Ерлану B плюс 10 со вчерашнего груза."` → ровно 4 сущности: announcement, task u-003, task u-005, points u-001 amount 10 (никакой пятой «выдуманной» задачи); `r-029-t` transcript `"Ерлан Т. образцы завтра утром, Ерлан Т. заказчик вечер."` → 2 task, обе `assignee_id: null`; `r-020` текст корпуса 020 → points u-002 amount −5, task u-001, task u-006 с `deadline_iso: null`; `r-023` текст корпуса 023 → recurrence без исполнителя, task u-003 (`deadline_iso: null`), task u-005 (`deadline_iso: null`, НЕ announcement); `r-024` текст корпуса 024 → task u-003 deadline 14.08 13:00 + points `assignee_id: null` (двое Ерланов без инициала).
7. `tests/ai/eval.ts` (запуск `tsx`, скрипт `eval:parser` в package.json; читает `.env.local` через `process.loadEnvFile` Node 24 или `dotenv` — что проще): для каждого кейса `parseTranscript` (+ `postprocess`), `now = frozen_now`, ростер `tests/stt/roster.json` с `is_active: true`. Скоринг по AI.md §6: entity-level P/R/F1 — жадное сопоставление предсказанных и ожидаемых по `(kind, assignee_id после matchName)`; assignee accuracy — по ожидаемым сущностям с полем `assignee_id` (ожидание `null` считается верным, если `assignee.status !== 'matched'`); deadline accuracy — среди сопоставленных с полем `deadline_iso` (|Δ| ≤ 30 мин, null-к-null верно); полнота мульти-разбиения — число сущностей совпало и `group_with` соблюдён; query/command accuracy — доля кейсов, где наличие `kind: query` совпало с ожиданием. Флаги: `--no-escalate`, `--filter <prefix>`, `--limit N`. Вывод: таблица метрик, список проваленных кейсов с diff (ожидание vs факт, коротко), суммарные токены/стоимость (по прайсу Haiku $1/$5 за Mтокенов, Sonnet 5 — $3/$15; cache_read по 0.1× входа) и p50 латентности. Запись `tests/ai/results/YYYY-MM-DD_HHmm.json` (метрики + по-кейсовые результаты) и diff с предыдущим файлом (какие кейсы сломались/починились). Код выхода 1, если assignee < 0.97 или F1 < 0.90 (флаг `--no-gate` только печатает).
8. Прогнать `pnpm eval:parser` дважды (второй прогон — проверка кэша: `cache_read_input_tokens > 0` в сумме; если 0 — искать изменчивое содержимое в system/few-shot, это баг). Результаты закоммитить. **Если гейт красный — промпт НЕ править** (это работа архитектора): зафиксировать проваленные кейсы в отчёте и WORKLOG, закоммитить как есть.
