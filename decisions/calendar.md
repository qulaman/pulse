# Календарь

### D-78. Календарь: сущность `event` через тот же конвейер, участники списком, напоминание через outbox · 🟡 ждёт визы
**Решение.** Мероприятие — сущность парсера `event` и таблицы `events` + `event_participants`.
- маркер (собрание, планёрка, встреча, выезд…) и время дают `event`; «всем …» — `everyone: true`; поручение рядом — отдельный `task`
- участники — список, id ставит постобработка; автор всегда участник; нет времени — блокирует (`time_missing`), дата без времени — 09:00 с жёлтым чипом
- видит директор — всё, остальные — свои; `tv` таблиц не читает
- приглашение, перенос, отмена ждут окна доставки; напоминание (`remind_before_min`, по умолчанию 30) и отказ — сразу
- ответ «Буду» / «Не смогу» — `respond_event`, абсолютный, без `client_request_id`
**Не делаем.** Telegram-ярус, правку участниками, утреннюю сводку.
**В коде.** Миграция `20260918150000_calendar_events.sql` (`events_due_reminders`), `lib/ai/postprocess.ts`, `lib/calendar/`.
**Связи.** Форма и удаление — D-94; вид — D-100; стена — D-96, D-98; серии встреч — D-148.
**Виза.** Участники отвечают «Буду / Не смогу», напоминание — за 30 минут, менеджер видит только свои встречи — оставить так?

### D-94. Полноценный календарь: вкладка, месяц с лентой, одна форма создания и правки, удаление · 🟡 ждёт визы
**Решение.** «Календарь» — вкладка у всех людей после «Задач» / «Дел».
- одна форма (`EventEditor`) для создания и правки; создание идёт через `confirm_voice_batch`: `events` пишет одна функция
- правка — RPC `edit_event` целиком: убранным — «Отмена», оставшимся — «Перенос», добавленным — приглашение; извещение, ждущее окна, переписывается, а не догоняется вторым
- удаление — `delete_event`, строки нет ни у кого; знавшим о будущей встрече — «Отмена»
- правит и удаляет только директор
**Не делаем.** Дневной вид, правку участниками.
**В коде.** `components/calendar/EventEditor.tsx`, `lib/calendar/mutations.ts`, миграция `20260923200000_calendar_edit_delete.sql`.
**Связи.** Уточняет D-78; вид — D-100; серии встреч — D-148.
**Виза.** Встречу можно создать и поправить формой и удалить совсем, а участники получают одно извещение — оставить так?

### D-100. «Календарь» языком «Задач»: экран статуса с полосой дня, месяц сворачивается в неделю · 🟡 ждёт визы
**Решение.** `/calendar` построен как «Задачи».
- экран статуса — одно число и фраза, громкое первым, и полоса дня 08–20 со стрелкой «сейчас»; считается по окну «вчера + 30 дней», а не по показанному месяцу
- месяц сворачивается в неделю, выбор помнит телефон
- лента от выбранного дня — карточки, до 40, дальше «Показать ещё»; карточка раскрывается на месте, открыта одна; `?e=<id>` из пуша открывает её
- экран рисуется после гидратации, до того — скелетон
**В коде.** `components/calendar/{CalendarView,CalendarStatus,MonthGrid}.tsx`, `lib/calendar/overview.ts`.
**Связи.** Уточняет D-94, D-78; строка статуса открывает свою встречу — D-143.
**Виза.** Календарь выглядит как «Задачи»: сводка дня, месяц сворачивается в неделю, встречи раскрываются на месте — оставить так?
