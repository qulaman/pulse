# STT_GATE.md — замер распознавания речи на корпусе фраз

Протокол замера STT: как записать корпус, что считает скрипт, какие пороги должна пройти конфигурация. Для того, кто сравнивает провайдеров или настройки распознавания. Как продукт зовёт STT — docs/AI.md §1, выбор провайдера компании — docs/AI.md §15. Итог прогона — запись в WORKLOG.md, смена провайдера — решение в DECISIONS.md. Казахская речь — открытый вопрос (D-17), ответ дадут категории D и E этого корпуса.

Файлы: `tests/stt/corpus.jsonl` (фразы и эталоны), `tests/stt/roster.json` (демо-ростер), `tests/stt/run.mjs` (прогон), `tests/stt/RECORDING.md` (шпаргалка записи), `tests/stt/record.html` (запись в браузере), `tests/stt/session-logs/` (журналы записи).

Правила: провайдер выбирается по метрикам §4, не на слух (D-39, D-53); правка фразы корпуса — правка её кейса в `tests/ai/parser_evals.jsonl`, если он есть; аудио корпуса в git не попадает.

## 1. Корпус

| Категория | Фраз | Что |
|---|---|---|
| A | 15 | одна задача: исполнитель, суть, срок |
| B | 8 | несколько поручений одним монологом |
| C | 7 | телеграф: «марат кп казхром завтра до обеда, ерлану +10» |
| D | 10 | казахские имена в падежах и казахские фрагменты в русской фразе |
| E | 6 | реальный шум: цех, машина, улица |
| F | 4 | вопросы к системе |

Строка корпуса: `id`, `category`, `text` (дословный эталон), `names` — упоминания людей с `surface` и `user_id`; имя, которое двое делят без фамилии, помечено `ambiguous`. Корпус должен держать не меньше 60 упоминаний имён (с падежными и казахскими формами) и 5 упоминаний контрагентов. Он написан на демо-ростере; для клиента имена заменяются реальными, фразы и число упоминаний сохраняются (`tests/stt/RECORDING.md`).

## 2. Протокол записи (D-42)

- Записывает сам директор, в своей манере, на свой телефон.
- Каждая фраза — дважды: встроенный микрофон и гарнитура; категория E — в реальном шуме.
- `m4a` в максимальном качестве, напрямую, не через мессенджер.
- Имя файла — `NNN_{категория}_{phone|headset}.m4a`, например 016_B_phone.m4a.

«СТТ-студия» `tests/stt/record.html` записывает фразу в браузере и скачивает файл и журнал сессии. Её собственное распознавание и разбор идут со старыми промптами (подсказка списком, прежний промпт парсера) и замером не считаются.

## 3. Хранение

Аудио — в каталоге fixtures внутри `tests/stt/`, только локально. Прогон берёт лишь файлы с именем по шаблону §2 прямо в этом каталоге. Он пишет рядом результаты (каталог results, вне git) и манифест manifest.jsonl — строка на файл с эталоном и упоминаниями.

## 4. Метрики и формулы

Нормализация (`normalize` в `tests/stt/run.mjs`, копия — `lib/text/normalize.ts` у продукта): нижний регистр, «ё» как «е», без пунктуации, числительные словами — цифрами. Основа слова — рекурсивное отсечение окончаний `-ға -ге -қа -ке -ды -ді -ты -ті -ом -ой -ей -у -е -а -ы -ю -я`, пока остаётся не меньше трёх букв: «Ерлану» и «Ерланға» сходятся с «Ерлан».

NameRecall = найденные упоминания / все упоминания. Упоминание найдено, если в транскрипте есть каждое его слово: по основе, а токен до двух букв (инициал) — точно.

Адресат проверяется по упоминаниям без `ambiguous` матчером самого скрипта (не LLM и не `lib/matchName.ts`: меряется STT, а не парсер). Человек однозначно есть в транскрипте, если там основа его имени и такое имя в ростере одно, или целиком его многословная форма. Correct — эталонный человек однозначно есть; wrong — его нет, но однозначно есть человек, которого во фразе нет вовсе; иначе miss. AssigneeAccuracy = correct / total; WrongAssigneeRate = wrong / total.

WER = (S + D + I) / N по нормализованному тексту, среднее по файлам, — только для сравнения провайдеров.

Почему имена, а не WER: продукт ломает одно слово — имя. Miss поправим (красный чип «Кому?»), wrong отправляет задачу не тому, и директор узнаёт через день. Поэтому порог на wrong почти нулевой (D-16).

## 5. Провайдеры и конфигурации прогона

| Конфигурация | Что шлёт скрипт | Отличие от продукта |
|---|---|---|
| `gpt4o` | `gpt-4o-transcribe`, подсказка-предложение из демо-ростера | — |
| `gpt4o-noroster` | без подсказки | вклад подсказки |
| `whisper` | `whisper-1` с той же подсказкой | базовая линия |
| `deepgram` | `nova-3`, имена и контрагенты в `keywords` | продукт шлёт `keyterm` |
| `scribe` | `scribe_v2` без keyterms | продукт шлёт слова компании |

По умолчанию — подсказка языка `ru` и файлы `phone`; продукт по умолчанию язык не подсказывает. Файл отправляется как `audio/mp4`.

## 6. Скрипт `pnpm test:stt`

`pnpm test:stt` — `node tests/stt/run.mjs` с флагами `--providers`, `--mic phone|headset|all`, `--lang ru|none`, `--fixtures <каталог>`, `--stamp <имя>`. Ключи — только из окружения (`OPENAI_API_KEY`, `DEEPGRAM_API_KEY`, `ELEVENLABS_API_KEY`); конфигурация без ключа пропускается.

Скрипт гонит каждый файл через каждую конфигурацию и печатает таблицу: проход порога §7, NameRecall, AssigneeAcc, WrongRate, WER, медиана задержки, стоимость — с отдельными строками категорий D и E; пишет результат и манифест; печатает изменение NameRecall к прошлому прогону. `node tests/stt/run.mjs smoke <файл> "<эталон>"` — проверка одного файла: транскрипт, найденные люди, WER; это не замер.

## 7. Пороги и что пробовать

Конфигурация проходит, если на микрофоне `phone` NameRecall не ниже 95%, AssigneeAccuracy не ниже 90% и WrongAssigneeRate не выше 2%. Лучшая — кандидат в `settings.stt.provider`, вторая — в `settings.stt.fallback`. Результат на гарнитуре — вход в D-42. У WER порога нет; для смешанной речи ориентир — около 15%.

Не проходит — по одной ступени за итерацию:

1. Без подсказки языка (`--lang none`): не режет ли `ru` казахские вставки.
2. Варианты подсказки — всегда предложением (D-53), не больше 60 человек (D-55).
3. Проходит только гарнитура — пометка «гарнитура обязательна», вход в D-42.
4. Усиление ключевых слов Deepgram, свежие модели провайдеров.
5. Ничего не помогло — смена провайдера, решение владельца.

## Известные ограничения

- Корпус не записан: файлов по шаблону нет, полного прогона не было.
- Deepgram и Scribe настроены иначе, чем в продукте (§5).
- Цены минуты в скрипте — свои оценки, не `lib/ai/pricing.ts`.
