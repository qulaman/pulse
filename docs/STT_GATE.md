# STT_GATE.md — этап 0 (гейт перед UI): выбор STT-провайдера по данным

Что это: протокол этапа 0 (docs/CONCEPT.md §7) — для того, кто прогоняет корпус и фиксирует выбор STT. Арбитр — `DECISIONS.md`. Решение о STT-провайдере принимается ДО написания UI и только по результатам этого протокола (D-17, D-39, D-40(в)). «На слух вроде норм» — не результат. Итог гейта — запись решения в `DECISIONS.md` (закрытие D-17) + отчёт в WORKLOG.md.

## 1. Корпус: 50 фраз

| Категория | Кол-во | Содержание |
|---|---|---|
| A. Одиночные задачи | 15 | Один исполнитель, суть, дедлайн (явный и конвенционный: «до обеда», «к пятнице») |
| B. Мульти-сущности | 8 | 3–5 поручений в одном монологе: объявление + задачи + очки, «как на планёрке» |
| C. Телеграфный стиль | 7 | «марат кп казхром завтра до обеда, ерлану +10» — без связок и глаголов |
| D. Казахские имена и вставки казахского | 10 | Имена в падежах обоих языков («Ерлану», «Маратқа», «Сәкенге»), целые казахские фрагменты в русской фразе |
| E. Шум | 6 | Записаны в реальном шуме: цех, салон машины, улица (не наложенный шум) |
| F. Вопросы к системе | 4 | «Что там по Казхрому?», «Кто не отчитался?» — для будущей классификации query/command |

Требования к корпусу: суммарно **≥60 упоминаний имён сотрудников** из реального ростера компании клиента (на этапе 0 — клиент №1), включая падежные и казахские формы; ≥5 упоминаний контрагентов/топонимов («Казхром», объекты). Тексты 50 фраз фиксируются заранее в `tests/stt/corpus.jsonl` (по строке: id, категория, текст, упоминания имён с user_id; неоднозначные «Ерлан» помечены `ambiguous` и исключаются из adressee-метрик) — **этот файл — единый источник**: те же фразы становятся eval-фикстурами парсера (`tests/ai/parser_evals.jsonl`) и донором few-shot примеров (`lib/ai/examples.ts`). Правка фразы = правка во всех трёх местах.

## 2. Протокол записи (директор, D-42)

- Записывает **сам директор** в своей обычной манере речи (не «диктовка диктора»), на **свой телефон** — тот же микрофон, что будет в проде.
- **Каждая фраза — дважды: встроенный микрофон телефона и гарнитура/петличка** (A/B-сравнение микрофонов, D-42). Итого 100 файлов. Категория E — оба дубля в реальном шуме.
- Формат: `audio/mp4` (m4a/AAC) в максимальном качестве, запись напрямую (диктофон/тестовая страница), НЕ через мессенджер (транскодирование убьёт сравнение).
- Именование: `NNN_{cat}_{mic}.m4a`, напр. `017_D_headset.m4a`.

## 3. Хранение фикстур

- Аудио: bucket Supabase Storage `stt-fixtures` (или git-lfs); локально скачиваются скриптом `pnpm stt:fetch` в `tests/stt/fixtures/` (каталог в `.gitignore`).
- В git: `tests/stt/corpus.jsonl` (тексты + эталонные имена) и генерируемый скриптом `tests/stt/manifest.jsonl` — по строке на файл:

```json
{"id":"017","file":"017_D_headset.m4a","category":"D","mic":"headset","duration_ms":8400,
 "reference_text":"Сәкенге айт, объект бойынша фотоотчёт жіберсін бүгін кешке",
 "names":[{"surface":"Сәкенге","user_id":"u-004"}]}
```

`reference_text` — дословный эталон, казахские фрагменты в оригинальной орфографии. `names[]` — все упоминания сотрудников с привязкой к id ростера (эталон для метрик №1–2).

## 4. Метрики и формулы

Нормализация текста перед всеми метриками: нижний регистр, `ё→е`, удалить пунктуацию. Стем имени: усечение падежных окончаний русских (`-у, -е, -ом, -а, -ы, -ой`) и казахских (`-ға, -ге, -қа, -ке, -ды, -ді`) — «Ерлан*» засчитывает «Ерлану» и «Ерланға».

**Метрика 1 — Name Recall (гейт: ≥95%).**
`NameRecall = (число эталонных имён, чей стем найден в нормализованном транскрипте) / (всего имён в эталонах корпуса)`

**Метрика 2 — поле-метрики карточки (гейт: адресат ≥90%, ошибочный адресат ≤2%, цель 0%).**
Каждое эталонное имя прогоняется через детерминированный `matchName` (см. docs/AI.md §5, без LLM — гейт меряет STT, не Claude) над транскриптом:
- верный `user_id` → correct; чужой `user_id` → wrong; не найден → miss.
- `AssigneeAccuracy = correct / total ≥ 0.90`
- `WrongAssigneeRate = wrong / total ≤ 0.02`

**Почему это жёстче WER:** WER штрафует все слова одинаково, а продукт ломает одно слово — имя. Ошибки асимметричны: *miss* восстановим (красный чип «Кому?», директор тапает выбор — терпим до 10%), *wrong* — катастрофа: при автоматизационной слепоте «Всё верно» задача уедет не тому человеку, и директор узнает об этом через день. Поэтому miss ≤10%, wrong ≈ 0.

**Метрика 3 — WER (справочно, не гейтует): ≤15%.**
`WER = (S + D + I) / N` (замены+удаления+вставки / слов в эталоне) по нормализованному тексту. Для смешанной русско-казахской речи 15% реалистичен; метрика нужна для сравнения провайдеров между собой, решение принимают метрики 1–2.

## 5. Провайдеры и конфигурации прогона

Все — через единый интерфейс `lib/ai/stt.ts` (контракт — docs/AI.md §1):

| Провайдер | Конфиг |
|---|---|
| `gpt-4o-transcribe` (primary-кандидат, D-39) | два прогона: с `prompt`-ростером имён и без — измерить вклад ростера |
| `whisper-1` | с `prompt`-ростером (базовая линия) |
| Deepgram `nova-3` | `keyterm`-boosting ростером |
| ElevenLabs Scribe | казахский 3.1% WER на FLEURS — проверить, держится ли на СМЕШАННОЙ речи, а не чистом казахском |

Базовая решётка: 4 провайдера × микрофон phone × language-hint `ru`. Дополнительно (по потребности, см. §7): без language-hint (D-17 — не режет ли `ru` казахские вставки), микрофон headset.

## 6. Скрипт `pnpm test:stt`

1. Читает manifest, гоняет каждый файл через каждую конфигурацию `провайдер×параметры`.
2. Считает метрики §4 по корпусу целиком и в разрезе категорий (отдельно D и E — они решающие).
3. Печатает таблицу `провайдер×конфиг → NameRecall | AssigneeAcc | WrongRate | WER | p50 latency | стоимость корпуса`.
4. Пишет `tests/stt/results/YYYY-MM-DD_HHmm.json`; повторный запуск печатает diff к прошлому.

## 7. Критерии прохода и действия при провале

**Проход:** существует `провайдер×конфиг` (на микрофоне phone), где одновременно NameRecall ≥95% ∧ AssigneeAccuracy ≥90% ∧ WrongRate ≤2%. Победитель → `STT_PROVIDER`, второй по метрикам → фолбэк-провайдер в env. Результат headset — вход в решение D-42 (покупать ли гарнитуру).

**Провал — лестница действий, по одной ступени за итерацию:**
1. Прогнать лучших кандидатов **без language-hint** (казахские вставки, D-17).
2. Вариации `prompt`-ростера: полные ФИО vs «имя + алиасы + контрагенты» (лимит ~224 токена).
3. Если проходит **только headset** — гейт пройден с пометкой «гарнитура обязательна», закупка по D-42 до этапа пилота.
4. Агрессивный keyterm-boosting Deepgram; свежие модели провайдеров, вышедшие к моменту гейта.
5. Ничего не помогло → **стоп-правило**: неделя на корпус/провайдера, План Б из D-39 (смена STT), решение владельца. UI не начинаем.
