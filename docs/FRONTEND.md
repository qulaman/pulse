# FRONTEND.md — устройство клиента

Как построен клиент Pulse — от маршрутов до работы без сети. Для агента с нарядом в клиентском слое и для нового разработчика. Экраны описаны в `docs/SCREENS.md`; визуальный язык, токены и маскот — в `docs/DESIGN.md`; роуты, RPC и доставка уведомлений — в `docs/BACKEND.md`; схема и RLS — в `docs/DATABASE.md`; серверная часть голосового конвейера — в `docs/AI.md`; тесты — в `docs/TESTING.md`.

## 2. Правила слоя

1. Серверным состоянием владеет только TanStack Query; Zustand держит эфемерное и никогда — данные из базы (D-39).
2. На Realtime подписываются только через `lib/realtime/useRealtimeQuery.ts` (D-126).
3. Каждая мутация несёт `client_request_id`, выданный один раз на тап: пауза, повтор и досылка — тот же вызов (принцип 7, G.3). Без ключа — только абсолютные команды, повтор которых пишет то же состояние (D-76 §3).
4. Запись в несколько таблиц — только API-роутом или RPC; напрямую браузер пишет одну строку под RLS.
5. Роль проверяет layout группы; `proxy.ts` только маршрутизирует. Группы не видны в URL — гард нужен в каждой.
6. Первый кадр браузера совпадает с HTML сервера; браузерное появляется после гидратации (раздел 4).
7. Тап пишет данные сразу; эффект играет поверх и ничего не задерживает (принцип 1a).
8. Записанное и набранное лежит на телефоне, пока не дошло до сервера (принцип 5, D-130).
9. zod не попадает в браузерный бандл (D-126).
10. Анимации — только transform и opacity; `animationiteration` никто не слушает (D-131).
11. Заглушка загрузки — сам экран до первого блока, зависящего от данных (D-122).
12. Тексты интерфейса — русские и без имени клиента, комментарии — английские.

## 3. Навигация и роутинг

### 3.1. Маршруты и оболочки

Layout читает сессию (`getSessionProfile`), проверяет роль и оборачивает экран. Чужую роль он уводит на её дом (`homeForRole`), нет или отозвана сессия (`AuthError`) — на `/login`.

| Маршруты | Оболочка | Кого пускает |
|---|---|---|
| `/pulse`, `/sent`, `/confirm`, `/notes`, `/screen`, `/admin` | `app/(director)/layout.tsx` → `DirectorShell` | директора |
| `/feed`, `/tasks` | `app/(employee)/layout.tsx` | команду (`TEAM_ROLES`) |
| `/settings`, `/people/*` | `AdminShell`: директору — `DirectorShell`, секретарю — её бар | директора и секретаря (D-104) |
| `/reports` | `DirectorShell` | директора |
| `/report` | своя | команду |
| `/secretary` | своя | директора и секретаря |
| `/lab/*` | своя, `labOpen` | директора и секретаря при `settings.dev_tools`, команду при `settings.lab_for_all` (D-150) |
| `/tasks/[id]`, `/calendar`, `/ether`, `/rating`, `/shop`, `/profile` | своя у каждого | любого вошедшего; данные режет RLS |
| `/tv` | без навигации | киоск `tv` и директора |
| `/desk/*` | `DeskShell` | директора и секретаря |
| `/ops/*` | своя сессия оператора | разработчиков (D-157) |
| `/`, `/login`, `/c/[slug]` | публичные | с сессией прокси ведёт домой |
| `/dev/*` | `app/dev/layout.tsx` | только dev |

`DirectorShell` монтирует ещё `DirectorFab` (пилюля черновика, шторка «Дать задачу», оверлей конвейера; микрофона нет, D-92), `NotesReplay` и `KeptPhrases`. Корневой layout монтирует досылки, плашку сети, обновление, тосты, вибрацию, `PushSync` и `SessionWatch`; всё, что относится к жизни компании, — внутри `NotOnOps`, в консоли его нет.

### 3.2. Прокси

`proxy.ts` (в Next 16 он заменил middleware) не видит `/api/`, `/_next/` и файлы с расширением. Порядок:

1. `/ops` уходит в `lib/ops/proxy.ts`; при заданном `OPS_HOST` его хост ведёт только в консоль.
2. `createServerClient` и сразу `getClaims()` — код между ними ломает обновление сессии. `getClaims` проверяет JWT на месте (D-126).
3. Нет сессии: публичное пропускается, остальное — на `/login`.
4. Сессия на `/`, `/login`, `/c/<slug>`: прокси читает роль и ведёт на `homeForRole` (`lib/routes.ts`: директор — `/pulse`, команда — `/feed`, киоск — `/tv`, прочие — `/profile`), а директора и секретаря на компьютере — на `deskHomeFor`. Сессия без профиля остаётся на `/login`.
5. Компьютер на телефонном адресе с двойником (`mayHaveDeskRoute`) — роль и `deskRouteFor(pathname, search, role)`.

Роль читается только в шагах 4 и 5; редирект переносит обновлённые cookie.

### 3.3. Телефон или компьютер

Решает устройство, не ширина окна (D-153): `isDesktopUa` (`lib/desk/device.ts`) смотрит `sec-ch-ua-mobile`, без него — user agent. Cookie `pulse_view=phone` на год держит компьютер на телефонных экранах; ставит её `goPhoneView`, снимает `goDeskView`, обе — полной загрузкой. Двойники адресов, навигация десктопа и экраны только директора — `lib/desk/routes.ts` (`deskRouteFor`, `DESK_NAV`, `deskAllows`); двойник переносит только параметры, которые читает его экран.

### 3.4. Оболочки

**Таб-бар** (`components/TabBar.tsx`, D-112). Число на «Делах» — дела, ждущие хода человека (`useFreshTaskCount`, фильтр `myMoveFilter` из `lib/tasks/my-move.ts`): то же правило у значка приложения (`/api/push/badge`) и у шарика «Дела» в Ленте (D-173). Набор вкладок решает сервер (`tabScope` в `lib/lab/access.ts`), первый кадр — уже со всеми. Вложенный экран подсвечивает вкладку раздела (`SECTIONS`), туда же ведёт «Назад» (`backTarget`). `ADMIN_TABS_ON_PHONE = false`: «Настройки» и «Лаб» открываются из «Профиля» (D-153). Пристыкованное над баром стоит на `var(--tabbar-space)` с классом `.above-tabbar`; панель над баром сообщает высоту через `useDockSpace` (`--dock-space`), нижние тосты встают над ней.

**`RoleScope`** даёт роль бара (`useTabRole`), признак «Лаб» (`useLabTab`), кладёт профиль в кэш (раздел 4) и ведёт имена компании для `shortName` (`lib/people/names.ts`, D-146).

**Десктоп** (`app/desk/layout.tsx`). `DeskShell` уводит секретаря с экранов директора (`deskAllows`); `DeskScope` делает то же, что `RoleScope`. Данные — те же хуки `lib/**`, ссылки телефонных компонентов на двойник переводит `DeskLinks`. Атрибуты `data-surface="desk"` и тему на `<html>` ставит `DESK_SHEET_SCRIPT` в `<head>` до отрисовки (иначе мигнут телефонные токены); под ними `app/globals.css` обнуляет телефонные отступы и рисует `Sheet` диалогом. Клавиши — `lib/desk/keys.ts`, порядок Esc — `components/desk/ui/layers.ts`.

**Консоль** `/ops`: `app/ops/(console)/layout.tsx` без сессии оператора не рисует рамку; `OpsProviders` создаёт свой `QueryClient` без повторов — его данные не попадают в снимок.

## 4. Сервер и клиент

Серверная часть экрана — оболочка и сессия. `getSessionProfile` и `loadBrand` обёрнуты в `cache()`: layout и страница рендерятся параллельно, а запрос — один (D-126). Экраны с данными — клиентские и читают через TanStack Query; серверная страница читает роль и параметры адреса, базу — только `app/profile/(screen)/page.tsx` и `app/desk/profile/page.tsx`. Бренд читается service role: экран входа показывают до входа.

С сервера в кэш попадает одно значение — профиль. `RoleScope` и `DeskScope` кладут его под `["me"]` в инициализаторе `useState`, на сервере и в браузере одинаково и только в пустой кэш; `useMe()` получает его сразу. Остальное — пропсами. `HydrationBoundary` и `initialData` не используются.

Правила против ошибки гидратации React #418:

- API браузера (хранилище, `matchMedia`) читаются через `useSyncExternalStore` с серверным снимком или `useHydrated()` (`lib/useHydrated.ts`).
- Данные, попавшие в кэш до конца гидратации, ломают её, если их читает ещё не гидратированная часть. Снимок с телефона и прогрев вкладок ждут `afterHydration()` (`lib/offline/persist.ts`): она ищет в дереве React недогидратированные Suspense-границы. Строка поручения десктопа грузит людей при первом фокусе, а не при монтировании.
- `next/dynamic` с `ssr: false`, бейджи таб-бара и спящее кольцо шариков появляются после гидратации; `StillLogo` первым рендером отдаёт пустой `<span>`.
- Атрибуты от ранних скриптов допускает `suppressHydrationWarning` на `<html>`; корневой layout не читает `headers()`, зависящее от адреса решает `usePathname`.

## 5. Серверное состояние

**Где.** Домен держит в своей папке `lib/` пару: `queries.ts` — фабрика ключей (`taskKeys`, `noteKeys`, `calendarKeys`…), чтение и хуки; `mutations.ts` — хуки `useMutation`. Чистая логика — соседними модулями с тестами. Экран в базу не ходит, он зовёт хук.

**Ключи** начинаются с домена (`["tasks", "mine", userId]`, `["task-thread", taskId]`, `["roster"]`), и префикс достаёт все списки домена: всё со строками задач — под `taskKeys.root = ["tasks"]`. Размер загруженной страницы в ключ не входит, он лежит в маленьком сторе рядом (`useSentPages`): правка находит список под тем же ключом, рефетч хранит открытые страницы.

**Чтение** — `createBrowserSupabase()` (`lib/supabase/client.ts`, один клиент на вкладку) под RLS или `fetch` к роуту, где ответ собирает сервер (`/api/settings`, `/api/me`). Компанию не фильтруют — это делает RLS; фильтр по человеку ставят явно, где RLS отдала бы больше (руководителю — задачи подчинённых).

**Умолчания** (`QueryProvider`): `staleTime` 30 с; `gcTime` сутки — данные с телефона доживают до экранов, открытых позже; один повтор; без рефетча на фокус — возврат из фона ведёт Realtime. Свой `staleTime` у редкого (`useMe`, ростер — 5 мин). `meta: { keep: false }` — не хранить на телефоне.

**Списки** — страницами по тапу, без `useInfiniteQuery` и виртуализации: переписка — 50 последних и «Показать раньше», закрытые задачи — по 100 (`useClosedPages`), заметки — 300 и по 200.

**Предзагрузка вкладок** (D-136). Ссылки таб-бара — `<Link prefetch>`; кэш роутера держит такую копию 30 мин, посещённый экран — 5 мин (`staleTimes` в `next.config.ts`), вход и выход сбрасывают его. После гидратации и 1,5 с бар один раз грузит списки вкладок теми же ключами и чтением, что экраны (`warmSentTasks`, `warmMyTasks` и др.). Ссылки «по одной на карточку» — `prefetch={false}`.

## 6. Realtime

`lib/realtime/useRealtimeQuery.ts`, три хука:

- `useRealtimeQuery({ queryKey, queryFn, channel, onEvent? })` — запрос с подпиской; без `onEvent` событие инвалидирует запрос, с ним экран правит кэш из payload.
- `useRealtimeListener` — канал без своего запроса, правит чужой кэш.
- `useRealtimeInvalidate` — событие инвалидирует чужой запрос.

`channel` — `{ table, filter?, event? }`, фильтр PostgREST (`assignee_id=eq.<uuid>`); фильтр сужает сокет, RLS — ещё раз на сервере.

**Общий канал.** Один канал на тему «таблица + фильтр + событие» на вкладку; первый хук создаёт его, остальные добавляют слушателей. Перед подпиской канал передаёт сокету токен сессии (`realtime.setAuth`), иначе на жёсткой загрузке он входил анонимом и RLS не пропускала событий. После последнего слушателя канал живёт 30 с; событие без слушателей помечает канал, и следующий слушатель берёт снимок.

**Снимки.** `SUBSCRIBED` не значит, что слушатель WAL готов: изменение в ближайшие 1–2 с теряется. Через 2,5 с после каждой подписки слушатели перечитывают запрос. WebSocket свёрнутой PWA умирает молча, поэтому `visibilitychange` в видимое и `online` переподписывают канал и перечитывают всё; возврат быстрее 15 с при живом сокете ничего не трогает. Свой рефетч TanStack на `online` у этих запросов выключен.

**DELETE в канал с фильтром не приходит** — у удалённой строки есть только ключ. Списки задач слушают удаления отдельным каналом без фильтра (`useTaskDeletes`); новый фильтрованный список по таблице с удалениями должен сделать так же.

**Курсор `seq`.** Переписка (`useTaskMessages`) при пустом кэше читает 50 последних, дальше — только `seq > lastSeq`; `lastSeq` считается без оптимистичных строк (у них временный дробный `seq` и `meta.pending`). Ответ сливается с кэшем, каким тот стал к приходу ответа (D-142). `mergeBySeq` убирает дубли по `id`, пришедшая строка побеждает, порядок — по `seq`. INSERT идёт через курсор (в payload нет имени), UPDATE правит строку на месте.

**Доска Пульса** (`usePulseBoard`) — один запрос и два канала; событие `tasks` правит строку из payload, новая строка просит один рефетч на пачку событий за 150 мс.

## 7. Мутации

### 7.1. Пути записи и ключ

- **POST к роуту**: задачи (`postJson`, `lib/tasks/mutations.ts`), голос (`voiceApi`, `lib/voice/api.ts`), просьбы секретарю, отчёт за день.
- **`supabase.rpc()`** к функциям `security definer`: заявки, встречи, пульт стены.
- **Одна строка под RLS**: сообщение треда, заметка, доска.

Ключ выдаётся при тапе (`useTaskActions` зовёт `crypto.randomUUID()`), а не в `mutationFn`. Сообщение треда вставляется с id, выданным клиентом: оптимистичная строка и строка базы совпадают, дубль id значит «дошло». Без ключа — пульт стены (`lib/tv/mutations.ts`: `networkMode: "always"`, проверка `navigator.onLine`, потолок 12 с, без очереди) и правка и ответ на встречу (`lib/calendar/mutations.ts`).

### 7.2. Оптимистичная правка и откат

Образец — `lib/tasks/mutations.ts`. `onMutate` отменяет запросы под `["tasks"]`, снимает снимок всех кэшей с задачами и правит строку в каждом (`patchCached`). `onError` возвращает снимок и показывает тост словами сервера (`message_ru`) или «Не получилось». `onSettled` (`invalidateTasks`) только помечает списки устаревшими (`refetchType: "none"`) и перечитывает задачу и переписку: списки на экране обновит эхо Realtime (D-126).

401 — полная перезагрузка на `/login`, чтобы не осталось кэша мёртвой сессии. Сетевая ошибка кладёт вызов в `lib/outbox.ts` и бросает `NetworkError`: мутация (`networkMode: "offlineFirst"`) встаёт на паузу и доигрывается на `online`; повторы — только на сеть, до 6 раз с паузой до 15 с. Сообщение без сети остаётся в переписке с часиками.

### 7.3. Окно «Отменить»

«Принять», «Настоять», «Отозвать», «Удалить» директора пять секунд ждут «Отменить» (D-139, `lib/tasks/grace.ts`). Списки меняются при тапе, сервер узнаёт после окна, поэтому отмена — просто неотправка.

- `mutationFn` ждёт `holdForUndo`, потом зовёт `postJson`. «Отменить» отклоняет ожидание ошибкой `Undone`; `onError` откатывает только эту задачу (`rollbackTask`) и молчит.
- Окно принадлежит приложению: уход с экрана его не рвёт, уход в фон или `pagehide` отправляет ждущее сразу (`flushHolds`).
- Копия вызова лежит в очереди скрыто (`hold`) — умрёт приложение посреди окна, тап уйдёт на следующем запуске.
- Рефетч во время окна вернул бы старый вид — `keepOverlays` накладывает правку на каждый пришедший список задач.
- Вторая вкладка узнаёт об окне через `BroadcastChannel` и не досылает тап; запрет истекает через 30 с (D-142).

Просьба секретарю уходит сразу, её «Отменить» переводит заявку в `cancelled` (D-101).

### 7.4. Тосты

Кнопки сотрудника (`components/tasks/list/useEmployeeControls.tsx`): внутри `FlightTargetProvider` (Лента) `press` с узлом карточки играет полёт поверх уже записанного, тостов «Принято · в работе» и «Сдано на проверку» там нет; вне него — без движения и с тостами (D-167). Отчёт за день в Ленте — `useReportDue(now)` (`lib/daily-report/queries.ts`): `my_daily_report`, `companies.settings->daily_report->>ask_from` и своя `profiles.availability` под RLS (ключ `["daily-report","feed"]`); сдача, ждущая на телефоне (`useSubmitWaiting`), считается сданной, а `useRefreshMyDay` не перечитывает день, пока сдача в пути.

`toast(text, { action?, lifetimeMs?, windowMs? })` и `dismissToast(id)` (`components/ui/Toast.tsx`) зовутся откуда угодно, и вне React. Тост с кнопкой стоит внизу над баром и `--dock-space`, тап его не прячет (D-142); тонкая полоска внизу тает за `windowMs` — время, пока кнопку ещё можно нажать (по умолчанию вся жизнь тоста, D-166).

| `usePendingErrands` | `lib/errands/pending.ts` | просьбы секретарю, ждущие сети |
| `useUpdateRequest` | `lib/update/client.ts` | нажато «Обновить» |
| индекс имён | `lib/people/names.ts` | имена компании для `shortName` |
| `useSentPages` | `lib/tasks/queries.ts` | загруженные страницы и число строк |

Контекст — только у поддерева с общим: `RoleScope`, `DeskScope`, панель десктопа, черновик настроек (`components/settings/draft.tsx`).

### 8.2. Конвейер ввода директора

`lib/store/ingest.ts` — одна машина на голос и текст, оба ведут в один парсер. На Пульсе её играет лицо, на других экранах директора — оверлей `DirectorFab`, на десктопе — строка поручения и панель. Подписи и позы стадий — `lib/voice/stages.ts`: фраза не летит молча (D-43).

| Стадия | Что |
|---|---|
| `recording` | пишет `MediaRecorder`; громкость — через `subscribeIngestLevel`, без рендера на кадр; короче 1 с — ошибка |
| `uploading` | `/api/voice/upload-url`, файл — прямо в Storage по подписанной ссылке (G.8) |
| `transcribing` | `/api/voice/transcribe`; спереди клеится адресат, выбранный до записи |
| `parsing` | `/api/voice/parse` с `assignee_id` закреплённого человека (D-84); текст начинает отсюда |
| `confirm`, `sending`, `done` | карточки ждут правок и броска; `/api/voice/confirm` |
| `question` | во фразе только вопрос, отвечает ассистент |
| `kept` | нет сети, фраза оставлена на телефоне; через 1,5 с — `idle` |
| `error` | код и `retryFrom` — шаг для `retry()` |

После разбора `settle` решает: фраза из каталога — просьба секретарю (D-79); пустой разбор — экран «не разобрал»; одни заметки сохраняются сразу (D-75). Задача без броска не уходит (D-36). `clientRequestId` выдаётся в начале фразы и проходит все шаги; правка слов (`reparse`) — новый ключ, иначе сервер вернул бы старый результат.

**Копия на телефоне** (`lib/voice/kept.ts`, IndexedDB `pulse-voice`, D-130): запись кладётся до первого сетевого вызова, текст — до парсера, каждый шаг дописывается (путь в Storage, слова, карточки с правками, брошенная пачка). Копия стирается, когда пачка на сервере, фразу отменили или слов не было. Владельца связывает `KeptPhrases` (`bindIngestOwner`). Нет сети на шаге — стадия `kept`; бросок без сети сохраняет пачку и отвечает `{ queued: true }`. Пока фраза в работе, конвейер держит обновление приложения (`holdUpdate`).

**Запись** (`lib/voice/recorder.ts`): формат по порядку `audio/mp4`, `audio/webm;codecs=opus`, `audio/webm` — iOS не играет webm; микрофон без шумо- и эхоподавления; файл уходит целиком после отпускания (G.23). Плеер `components/tasks/VoicePlayer.tsx` берёт подписанную ссылку по первому тапу.

## 9. Офлайн

Background Sync на iOS нет: ждущее досылается, только пока приложение открыто.

### 9.1. Сервис-воркер

Свой `public/sw.js`, без фреймворка (next-pwa заброшен и не работает с App Router). Регистрация одна (`lib/offline/worker.ts`, её зовёт `QueryProvider` у всех): production — `/sw.js?offline=1`, dev — `/sw.js`; без флага воркер ничего не кэширует и стирает свои кэши. С флагом он отвечает на GET своего источника:

- **Файлы сборки** (`/_next/static/`, `/icons/`) — кэш первым, `pulse-static-v1`, до 600 файлов; имена по содержимому, копия не стареет.
- **Экраны** (навигации, кроме `/api/`, `/dev`, `/ops`, `/login`, `/c/`) — сеть первой; HTML 200 ложится в `pulse-pages-v1`, до 60 адресов. Сеть молчит 5 с — копия; нет сети и копии — страница «Нет связи», которая перезагрузится сама на `online`.

Не кэшируются API, не-GET, чужие источники (Supabase, ссылки на голосовые и фото), редиректы, вход и консоль. Новый воркер встаёт сразу (`skipWaiting`) и удаляет чужие кэши `pulse-*`: сменил формат кэша — смени имя.

Пуш: воркер показывает уведомление с тегом задачи и шлёт «увидел»; «Принял» в шторке делает переход со своим `client_request_id`, при неудаче открывает задачу. Запись мимо роутов зовёт `kickPush()`, чтобы пуш ушёл сразу (D-114).

### 9.2. Снимок данных

`lib/offline/persist.ts` хранит кэш запросов в IndexedDB `pulse-offline` (D-127): старт — с последних данных, без сети — они же.

- Берутся удачные запросы, кроме ключей на `admin` и `lab` и `meta: { keep: false }`; десктоп тоже — он под тем же провайдером.
- Пишется через 1,5 с после изменений и сразу при уходе в фон.
- Поднимается после гидратации, только своей сборки (`BUILD.id`) и не старше 7 суток; `hydrate` не затирает пришедшее с сервера.
- Старт без сети сам выставляет `onlineManager.setOnline(false)` — события `offline` в этом случае нет.

### 9.3. Очереди неотправленного

| Очередь | Хранилище | Чья | Что | Досылает |
|---|---|---|---|---|
| паузы мутаций | память TanStack | вкладки | тапы без сети | TanStack на `online` |
| `lib/outbox.ts` | localStorage `pulse.outbox.v1` | браузера | роуты задач, `task_messages`, словарь, «Сдать отчёт» | `OutboxReplay` |
| фразы директора | IndexedDB `pulse-voice` | человека | запись, слова, карточки, пачка | `KeptPhrases`, `lib/voice/keptReplay.ts` |
| файлы переписки | IndexedDB `pulse-media` | человека | голосовое, фото, сдача с фото | `MediaReplay` |
| заметки | IndexedDB `pulse-notes` | человека | заметки, правки, доски | `NotesReplay`, `lib/notes/replay.ts` |
| просьбы секретарю | localStorage `pulse.errand.outbox.<userId>` | автора | просьбы директора | `ErrandReplay` |

Общее: запись хранит ключ тапа, и повтор дошедшего безвреден; отказ сервера говорится его словами, протухшее — тостом (D-130); файлы лежат как `ArrayBuffer` — WebKit в приватном режиме не берёт Blob в IndexedDB.

**`lib/outbox.ts`** получает запись, только когда `fetch` упал на сети (скрыто — на время окна «Отменить»). Нужна для закрытой вкладки: живая доигрывает паузу сама. `OutboxReplay` досылает на старте и на `online`, если пауз в памяти нет, от старых к новым. Сеть, 5xx и 401 останавливают проход; 2xx и 4xx закрывают запись, 4xx — тостом. Старше суток — выброс с тостом. Потом инвалидируются задачи, переписка, настройки, люди, словарь, отчёты.

**Фразы и файлы** досылаются на старте, `online`, возврате и раз в 30 с, с того шага, где остановились, под теми же ключами. Разобранные карточки фразы ждут директора (D-36), брошенная пачка уходит. Одну фразу несёт один носитель — захват во вкладке и Web Lock между вкладками. Отказ сервера — попытка, после трёх решает человек. Файл грузится в Storage под тем же ключом, потом вставляется сообщение с тем же id или делается переход с тем же ключом; фото перед этим сжимается до 1600 px (`lib/files/photo.ts`).

**Просьбы** — каждые 15 с, пока ждут; старше 20 минут не уходят (D-106). Число ждущего показывает `OfflineBanner`.

### 9.4. Вход и выход

Выход (`components/profile/SignOutRow.tsx`) спрашивает подтверждение; если ждут фразы или файлы этого человека — «Выйти, отправить потом» (уйдут, когда он войдёт снова) или «Стереть и выйти». Перед концом сессии телефон отписывается от пушей (`forgetThisDevice`, не дольше 1,5 с). Экран входа при открытии стирает снимок и сохранённые экраны (`wipeOffline`), файлы сборки остаются; удачный вход очищает кэш запросов и уходит на `/` с `router.refresh()`. Отозванную сессию ловит `SessionWatch`: на возврате и раз в 5 мин `/api/me`, на 401 или 403 — перезагрузка на `/login` (D-135).

### 9.5. Версия приложения

PWA живёт днями, и после деплоя код на экране старше сервера (D-115).

- Номер сборки `BUILD` (`lib/version.ts`) вшивает в оба бандла `next.config.ts`: `PULSE_BUILD_ID` (его даёт CI вне Vercel), иначе `VERCEL_DEPLOYMENT_ID`, иначе коммит. Часы конфиг не читает — воркеры сборки дали бы разные номера.
- `COMPAT` поднимают, когда прошлая сборка не может работать с сервером: роут поменял тело, RPC — аргументы, читаемая таблица — форму.
- `useServerVersion` спрашивает `/api/version` на старте, возврате, появлении сети и раз в 10 мин.
- `updateAction`: другая `COMPAT` — экран «Нужно обновиться»; другая сборка — строка «Обновить», после 30 мин в фоне без несохранённого — тихо; стена — сама. Несохранённое — мутации в полёте, `holdUpdate` / `useUpdateHold` и непустые поля без `data-update-safe`.

Очереди 9.3 к сборке не привязаны: формат очереди меняется только вместе с чтением прежнего.

## 10. Загрузка и производительность

**Заглушка — сам экран** (D-122). У экрана с данными есть `loading.tsx`, и страница, пока ждёт, рисует ту же композицию (`components/ui/PageSkeletons.tsx`, блоки — `components/ui/Skeleton.tsx`): экран до первого блока, чьё место зависит от данных, ниже — один растущий плейсхолдер; стоящее не двигается. Заглушки рендерит сервер: в них нет хуков и функций в пропсах. Next показывает `loading.tsx` первого нового сегмента, поэтому страница раздела с заглушкой лежит в группе `(screen)` (`app/people/(screen)`, `app/settings/(screen)` и др.), иначе вложенный экран получил бы заглушку раздела.

**Бандл.** Публичный env проверяется рукой (`lib/env.public.ts`); подписи настроек и правил пушей — из `lib/settings-plain.ts` и `lib/push/prefs-plain.ts`; модули со схемами клиент берёт только `import type`. Редкое и тяжёлое — `next/dynamic` (тревога секретаря, лицо на экране ошибки). Картинки — `<img>`. Логотип клиента — только `components/ui/StillLogo.tsx`: неподвижный кадр с canvas, анимированный SVG будил бы основной поток каждый кадр.

**Покой** (D-131). Слушатель `animationiteration`, который React вешает на корень, будит основной поток на каждой границе бесконечной CSS-петли; строка `QUIET_LOOPS` (`lib/design/quiet-loops.ts`) в `<head>` не даёт его зарегистрировать, поэтому `onAnimationIteration` не использовать. `MascotPower` останавливает лица вне экрана; помощники скольжения — `components/ui/motion.ts`.

**Клавиатура телефона** (`lib/ui/keyboard.ts`): ответ на неё пишется в DOM внутри события `visualViewport`, не через состояние React, и ничто не прокручивает страницу в ответ на прокрутку — иначе экран дрожит. Целевые телефоны — iPhone 16–18 и флагманы Android (D-136).

## 11. Game feel как механизм

- Данные меняются в `onMutate`, до сети; эффект читает новое состояние и играет, пока запрос летит.
- Бросок на Пульсе: тап запускает `send()` и позу `sending` одновременно; поза держится 1,2 с независимо от ответа, праздник — только после успеха.
- Отдельного слоя эффектов нет: они живут в маскоте и компонентах (`docs/DESIGN.md`). Звуков на телефоне нет (D-27).
- Очки (D-165). Число очков рисует `RollingNumber` (`components/ui/RollingNumber.tsx`) — единственный файл, который импортирует `@number-flow/react`.
  - Рост прокручивается, как табло; падение меняется сразу.
  - Баланс магазина крутится вниз, пока свой заказ в пути или удался.
  - При «уменьшить движение» число меняется сразу.
  - Первый рендер совпадает с серверным.
  - В Ленте `PointsFlight` (`components/pulse/PointsFlight.tsx`) по ключу `usePointsArrival` через 0,35 с отправляет копию пилюли «+N» в счётчик `data-points-target` (`HeaderPoints`). Полёт — `flyInto` с `lifted: false` и `arrivesAs`, 0,65 с. Нет счётчика на экране — нет полёта.

**Вибрация** (D-147, `lib/haptics.ts`). `TapHaptics` — один слушатель `click` на документе: тик 10 мс на всё нажимаемое (не на поля), после обработчиков. Свой узор (`haptic()`) глушит тик того же нажатия, `data-haptic="off"` снимает тик с жеста. На iOS Vibration API нет: тикает только палец на скрытом переключателе `HapticSwitch` внутри `Button`, `Chip`, `HeadButton`, `Row` и вкладок, а способ включается на iPhone в `/lab/haptics`. Нет API — тихо, без ошибки.

## 12. Соглашения

**Экран.** Папка в группе своей роли или своя с гардом в layout. `page.tsx` — клиентский, данные хуками; серверная страница — когда нужны роль или параметры адреса. Экрану с данными — `loading.tsx`, вложенному в раздел — группа `(screen)`. Экран без вкладки — строка в `SECTIONS`; десктопный двойник — строка в `deskRouteFor`. Песочница — `app/dev/`.

**Запрос.** В `queries.ts` домена: ключ из фабрики, чтение, хук. Живой — `useRealtimeQuery`, с каналом DELETE при фильтре. Вкладке, что открывается сразу, — функция `warm…` с теми же ключом и чтением.

**Мутация.** В `mutations.ts` домена: ключ при тапе, оптимистичная правка в `onMutate`, откат в `onError`, тост словами сервера, списки — устаревшими. Отменяемый тап — через `holdForUndo`; то, что должно пережить закрытую вкладку, — через очередь, хранимую по человеку.

**Стор** — только эфемерное, рядом с владельцем; общий — в `lib/store/`. Серверные модули начинаются с `import "server-only"`.

**Примитивы.** Телефон — `components/ui/` (`Button`, `Chip`, `Row`, `PageHead`, `Sheet`, `Toast`, `Skeleton`, поля даты `datetime`, «железо» пульта `device`); выбор людей — только `components/people/PeoplePicker.tsx` (D-108). Десктоп — `components/desk/ui/` (`DataGrid`, `DeskPanel`, `Dialog`, `Popover`, `Menu`, `Tooltip`, `Shortcuts`): на месте телефонных шторок у него свои поповеры и диалоги (D-156). Вид — `docs/DESIGN.md`.

## 13. Тестирование клиента

Vitest гоняет `*.test.ts` из `lib/` и `tests/` в Node — компонентных тестов нет, поэтому проверяемое живёт чистыми функциями в `lib/` (конвейер, очереди, `mergeBySeq`, двойники адресов, решение об обновлении). ## 15. Известные ограничения

- `loadBrand()` без id читает первую строку `companies`. Так его зовут корневой layout (акцент), layout команды (показ очков под именем) и `/tv` (название и логотип стены): в базе с несколькими компаниями там видны вид и выключатель первой.
- `lib/outbox.ts` — одна очередь на браузер, а не на человека; вход и выход её не чистят, и повтор идёт под сессией, открытой в момент повтора. Так же по браузеру хранится черновик отчёта за день (`lib/daily-report/draft.ts`, `pulse.daily-report.draft.v1`): его читают форма `/report` и «Сдать» в Ленте (`oneTapInput`).
- Без открытого приложения ничего не досылается: тап в закрытой PWA уйдёт при следующем запуске.
- После деплоя снимок прошлой сборки не поднимается: первый старт показывает заглушки.
- Голосовые и фото без сети не открываются: ссылка берётся по тапу и не кэшируется.
- Отзыв сессии открытый экран замечает на возврате или в пределах 5 минут.
- `lib/store/ui.ts` (тихий режим) объявлен, но ни один экран его не читает.
