# FRONTEND.md — PWA, экраны, ТВ-режим

Спецификация фронтенда Pulse (рабочее название продукта, D-20) — контракт для всех, кто реализует UI: экраны, компоненты, state, оффлайн, производительность. Продукт — коммерческий SaaS; всё описанное клиент-агностично, клиентская специфика живёт в `company.settings`. **Арбитр при противоречиях — `DECISIONS.md`.** Схемы данных — `docs/DATABASE.md`, API — `docs/BACKEND.md`.

## Метки построенности — читать первой

Порядок этапов и гейты — `docs/CONCEPT.md` §7 (календаря нет — D-46); судьба гейта адаптации — что из очков, магазина, ТВ и game feel считать пилотом — открытый вопрос владельцу (В-1, «Ждёт владельца» в DECISIONS.md). Разделы и пункты помечены по факту кода:

- **[есть]** — построено; описание — контракт. Раздел без метки — `[есть]`.
- **[за флагом: settings.<ключ>]** — построено, включается настройкой компании (очки и рейтинг — `points_enabled`, D-48).
- **[не построено]** — замысел; агент не реализует его без наряда, даже если он описан подробно.

Вёрстка не должна мешать следующим слоям, но код не пишется «авансом».

## Онбординг `[не построено]`

Сейчас есть только подсказка установки PWA (`components/InstallHint.tsx`) и служебная строка про push. Замысел — чек-лист онбординга как экран продукта, не инструкция на бумаге (`<OnboardingChecklist>`):

1. Детект in-app-браузера (Telegram/WhatsApp WebView) → экран «Открой в Safari/Chrome» ДО всех инструкций (инвайт-ссылку пришлют именно в мессенджер).
2. Установить PWA на главный экран (пошаговый оверлей со скринами под платформу; iOS ≥16.4 — иначе нет push).
3. **Доступ к микрофону — отдельный шаг с тестовой записью** («скажи что-нибудь — послушай себя»), НЕ в боевом флоу: первое удержание маскота не должно утыкаться в системный диалог.
4. Push-разрешение (после первого действия, см. выше) + привязка Telegram (deep-link на бота; Telegram-ярус тоже `[не построено]`, D-21).
5. Выключить оптимизацию батареи (MIUI/Xiaomi — экран с инструкцией).
6. Тестовый пуш «на глазах» → отметка о прохождении чек-листа в БД.

Один экран онбординга сотрудника: «Эфир — для всех, Лента — лично тебе». Кнопка Эфира — «Ознакомился», ленты — «Принял» (лексически разведены осознанно).

## Аудио

Сердце продукта; ошибка здесь ломает принцип 5 CLAUDE.md («аудио всегда доступно сотруднику»).

- **Матрица записи** — пробовать mimeType по порядку: `audio/mp4` → `audio/webm;codecs=opus` → `audio/webm`. Выбранный mimeType отправляется на бэкенд и **хранится в метаданных файла**. Причина: iOS Safari не пишет и не играет webm/opus; mp4/AAC играет везде.
- **Битрейт — приоритет качества STT: 32–64 kbps.** `audioBitsPerSecond` на iOS игнорируется — любое значение описывать как best-effort, «24kbps» контрактом НЕ является.
- **Запись уходит одним blob после отпускания** (`lib/voice/recorder.ts`, G.23). Стриминг чанков MediaRecorder с `timeslice` во время записи — рычаг метрики скорости (D-43) — `[не построено]`.
- Загрузка аудио — клиентом в Storage по signed URL (лимит Vercel 4.5 МБ; G.8).
- **Плеер — `VoicePlayer`** (`components/tasks/VoicePlayer.tsx`, D-66): волна из 28 баров, детерминированная по id записи (не `decodeAudioData` на клиенте — фриз на Redmi), длина — из `meta.duration_ms`, подписанный URL — по первому тапу; один плеер у голосового в треде и «Оригинала голосового» директора.
- **DoD голосового конвейера включает смоук-тест «запись на Android → воспроизведение на iPhone»** (и наоборот).

## Ввод директора — голос и текст

Плавающей кнопки микрофона нет (D-92): директор говорит и пишет только на Пульсе — удержание маскота и «потянуть вниз» (`MascotLever`, техконтракт ниже — его). На остальных экранах директора `DirectorFab` оставляет пилюлю черновика (разобранная, но не отправленная фраза), текстовый ввод по запросу экрана без своей кнопки (`ComposeSheet`: «Дать задачу» на карточке сотрудника, человек закреплён по id — D-84) и оверлей конвейера и ошибки. У «Заметок» свой диктофон (D-81) — он пишет заметку дословно, не задачу; микрофон в переписке задачи — ответ в треде. Оба входа (голос и текст) ведут в один парсер и один /confirm.

Техконтракт (walkie-talkie в вебе не работает без этого):
- Pointer Events + `setPointerCapture`; `touch-action: none`; `-webkit-user-select: none`; `-webkit-touch-callout: none`; `contextmenu` → `preventDefault()`.
- **Порог 250мс**: удержание ≥250мс → запись голоса (лицо раздувается по уровню микрофона — директор видит, что его слышат), отпустил → отправка; «потянуть вниз» → текстовый ввод (`TextSheet`). Чипы частых исполнителей и пресеты дедлайнов над клавиатурой — `[не построено]`.
- **Свайп вверх при удержании = отмена записи** (стандарт мессенджеров).
- Разрешение микрофона получено заранее на онбординге (см. выше).

Состояния: запись/ввод → «Распознаю…» → карточки на месте (на Пульсе — прямо под лицом, с других экранов — на `/confirm`). При ошибке — «Не расслышал» + повтор; аудио не теряется (лежит в outbox).

**Тихий режим** (свитч в шторке, без автоплея голосовых и будущего TTS, для встреч) — `[не построено]`. Входящие вопросы сотрудников — быстрые **ответы-чипы** («Да», «Нет», «Позже», «Действуй сам») одним тапом — `[есть]` (карточки «Задач», экран задачи, Пульс).

Звуковых эффектов в v1 нет вообще (D-27).

## Подтверждение фразы

**Штатное место подтверждения — сама доска, а не отдельная страница** (D-60, шестое уточнение). Конвейер доигрывает на Пульсе: лицо слушало и разбирало — оно же выкладывает карточки под себя (`ConfirmInline` в нижней полосе), над головой его слова «Понял так: 2 задачи» — без инструкций: о тапе говорит само лицо (состояние `offering`, DESIGN §3). Шарики на это время уходят. **Тап по маскоту = бросок**: если есть что отправлять — пачка летит (лицо играет `sending` и выбрасывает карточку из руки, строка «Отправляю…»; поза держится весь размах 1,2 с, даже если сервер ответил за полсекунды), если у задачи нет исполнителя — открывается «Кому?» первой такой карточки. Под карточками «Отменить» и, вне окна доставки, «отправлю утром · отправить сейчас». Удержание лица на это время выключено: фраза уже в руках.

Страница `/confirm` осталась **запаской**: черновик, с которым директор ушёл на другой экран, ждёт в пилюле `DirectorFab` и открывается там же, где и раньше (шапка «Понял так», `SendBar` «Отправить N из M»). Общее у обоих мест — `ConfirmList` (карточки, «Кому?», дедлайн) и `useSendBatch` (что уходит, какой тост, вопрос смешанной фразы после отправки). Оверлей конвейера на /pulse прогресс не рисует и на /confirm не уводит — доска подтверждает на месте.

Список распознанных сущностей карточками (`components/confirm/EntityCard.tsx`): 📢 объявление / ✅ задача / 🔔 напоминание / 🔁 повтор (`recurrence`) / 📝 заметка (`note`, D-75) / 📅 мероприятие (`event`, D-78) / ➕ очки — `[за флагом: settings.points_enabled]` (выключены — карточка приглушена и уходит в `skipped`, G.22, D-48). Контракт данных (единый для фронта и бэка): сущности — `lib/ai/schema.ts` (`Entity`, zod), результат матчинга — `AssigneeMatch` из `lib/matchName.ts`: `entity.assignee: {status:'matched'|'ambiguous'|'unmatched', user_id: string|null, candidates:{user_id, full_name, score}[], flag:'ok'|'check'}`; блокировка сущности — `entity.blocked` из `lib/ai/postprocess.ts`: `points_blocked`, `assignee_unmatched`, `time_missing` (мероприятие без времени).

- **Закреплённый исполнитель** (D-84): фраза, начатая с выбранного на Пульсе человека или из «Дать задачу» на его карточке, приходит с `assignee_id`; сервер ставит его всем сущностям с одним человеком зелёным «matched».
- **Без подтверждения сохраняются только заметки** (пачка из одних заметок — тост «Записал» + «Отменить», D-75 §4) **и заявки секретарю** (≤3 слов из каталога, D-79 §9).

Правки:
- **Тап по тексту карточки → инлайн-редактирование title** (клавиатура). Обязательно: удалять сущность и переговаривать всё голосовое из-за одной ошибки STT — недопустимо.
- **Кнопка «🎤 переговорить эту сущность»** — перезапись одной карточки без потери остальных — `[не построено]`.
- Правка суммы очков — тем же паттерном (тап → инлайн), за флагом `points_enabled`.
- Чип исполнителя → выбор из кандидатов; чип дедлайна → пресеты (сегодня 18:00, завтра 9:00, завтра 13:00, своя дата); свайп сущности влево — удалить.

Доверие и прозрачность:
- Поле с `confidence < 0.8` — жёлтый чип «проверь».
- Выведенный дедлайн показывает `deadline_source_text`: «так понял: „завтра до обеда“». Молчаливых дедлайнов нет; без названного срока — `null`, чип «без срока».
- Нераспознанный исполнитель — **красный чип «Кому?»** (тап → полный список), отправка этой сущности заблокирована, остальные не блокирует: кнопка **«Отправить N из M»**.
- Отложенная доставка вне окна 08:00–21:00 (D-38) — пометка «отправлю утром» + тап «отправить сейчас» (на доске — под карточками, на `/confirm` — в `SendBar`).

**Компактный режим при 5+ сущностях**: свёрнутые однострочные карточки (иконка + исполнитель + суть + дедлайн), тап разворачивает; невалидные подсвечены и подсчитаны; кнопка «Отправить N» — sticky снизу.

**Автоотправки задач нет никогда** (D-36): бросок — явный жест директора. Для `source='shared'` (Web Share Target, `[не построено]`) — особенно: подтверждение руками обязательно всегда (защита от prompt injection).

## Экраны сотрудника

Лента сотрудника — экран с маскотом, см. «Лента (/feed)» ниже (D-62). Переписка — только в задаче (тред, D-64): композер текст / 📷 фото / 🎤 голосовое — **удержание до 10 секунд с обратным отсчётом, без распознавания** (D-66), длина едет в `meta.duration_ms`. Реакции директора — `[не построено]`.

### Состояние задачи → набор кнопок карточки (ядро UI сотрудника)

| Статус | Кнопки/состояние карточки |
|---|---|
| `sent` | **Принял / Уточнить / Не могу** (три кнопки — принцип №2, не расширять) |
| `accepted` | **Выполнено** (+ композер всегда доступен) → шторка «приложи результат» (фото/текст/голос) → `pending_review` |
| `pending_review` | без кнопок: «На проверке у директора» |
| `rework` | авто-переход в `accepted` (повторный «Принял» не нужен) + push «Вернул на доработку: [комментарий]» |
| `done` | терминал, пометка ✓ |
| `declined` | у сотрудника — терминал с причиной; у директора карточка в «Требует вас»: **Переназначить** (клон в `sent` новому, старая закрывается со ссылкой) / **Отменить** / **Настоять** (возврат в `sent` с комментарием) |
| `revoked` | пометка «отозвано директором» (D-01) |

- «Уточнить» = сообщение с `meta.is_question` (не статус, D-03); флаг снимается ответом директора.
- **«Не могу» — причины-чипы**: «Это не ко мне» / «Занят срочным» / «Буду позже: [дата]» + свободный текст. Свободное поле без чипов — запрещено (на морозе на стройке никто не печатает).
- **«Выполнено» доступно и в /feed, и в /tasks.**
- `in_progress` в UI v1 не показывается (D-04).

### Мои дела (/tasks) — D-83

### Действия директора на карточке
Открытая задача: «Продлить» (шторка сроков с пресетами и календарём; «Без срока» снимает срок), «Переназначить» / «Передать» (выбор человека из ростера, задача уходит новому как новая, у прежнего закрывается с пометкой; на любой открытой, D-80 §5), «Отозвать». Отказ («Не могу»): «Настоять / Переназначить / Отменить». Приёмка: «Принять / Доработать» («Принять» без отката, D-80 §4; «Доработать» — с комментарием). «Удалить» — последней, со шторкой-подтверждением: чистка без следа (D-58). Изменения видны в хронологии треда системными строками.

### /confirm — нет тупиков
Главная кнопка панели всегда нажимается: «Отправить N из M» когда есть что слать; «Указать, кому» когда все задачи заблокированы на исполнителе (открывает первую); «Закрыть» когда отправлять нечего. В шапке «Понял так: …» — явный «Закрыть» (44 px), черновик при этом сбрасывается. Ничего не разобрано (пустой ответ парсера или «не берусь») — единый экран «Не разобрал. Услышал так: „…“» с кнопками «Исправить текст» (шторка с транскриптом → повторный разбор под новым `client_request_id`, иначе идемпотентность вернёт тот же пустой результат), «Сделать задачей», «Закрыть»; окно ошибки оверлея для этих случаев больше не показывается.

## Лента (/feed) — экран сотрудника (D-62: тот же маскот)

Экран при открытии = маскот в середине (без микрофона: сотрудник говорит внутри задачи, не лицу); спит, только если принимать нечего — иначе **зовёт** ещё до первого тапа (D-69). ## Магазин (/shop) — D-71

Экран открыт **любой вошедшей роли** и говорит каждой своё.

- **Сотрудник**: карточка баланса (точная `SUM(point_transactions)`, а не сумма последних 50 строк истории — цена сверяется с настоящим числом), витрина, «Мои заказы». В карточке товара — эмодзи (фото витрины пока нет), название, одна строка описания и цена. Кнопка «Обменять» есть только тогда, когда очков хватает; иначе полоска накопления и «Ещё N очков» — цель, а не запрет. Свой заказ в `pending` сотрудник отменяет сам (D-37), очки возвращаются ровно на сумму холда.
- **Директор**: не витрина, а **пульт** (D-71 §12–14). Экран отвечает по порядку вопросов руководителя. (1) **Герой** — чем магазин жил месяц: крупно число выданных наград (смысл магазина — не остатки на складе, а то, сколько людей что-то унесли), лицо ассистента, под чертой два факта: очки на руках у команды и сколько заказов ждёт. Статичное золотое сияние в углу карточки — «дорого» без анимации теней и фильтров (перф-контракт DESIGN §2); золото здесь уместно, это экран наград. (2) **«Выдать»** — секция есть, только когда есть что выдавать: аватар, имя, награда и «ждёт 3 часа»; ровно **одна крупная кнопка «Выдал»** и мелкая ссылка «Отменить». Промежуточного «Подтвердить» у директора нет — это ярус завхоза. (3) **«Награды»** — сетка плиток 2×N: значок на золотом ореоле, название, ценник-ярлык и строка жизни «взяли 3 раза» / «пока не брали»; состояние склада («скрыта», «нет на складе», «3 шт.») — ярлыком в углу. Последняя плитка — пунктирная «Добавить награду». Тап открывает лист-редактор с **живым превью** карточки сотрудника, чипами цен, чипом «Сколько угодно», переключателем «Показывать в магазине» и «Удалить награду»; сохранение — upsert по заранее выданному id (принцип 7), удаление возможно только у награды без заказов. (4) **«Кому что досталось»** — три последние выдачи с именами: магазин как событие, а не как склад. (5) **«Очки команды»** — два факта (роздано за месяц / унесено в магазин) и трое, кто ближе всех к своей награде («ещё 385 до „День отгула“»); построчная история — за тапом «Вся история очков», в шторке. (6) Ссылка **«Поощрить очками»** на Рейтинг: начисляют очки там (D-48). Появление блоков — лесенка 40 мс, только transform/opacity, под `prefers-reduced-motion` блоки просто стоят. Вход: «Настройки» → «Сотрудники» → «Магазин».
- **Завхоз**: витрина со своим балансом (он тоже копит очки) плюс очередь выдачи; свой заказ он не проводит — это делает директор.
- **Realtime**: `shop_items` и `orders` в публикации, баланс переспрашивается на события `point_transactions` — заказ, выдача и отмена доезжают на открытый экран без перезагрузки.
- **Входы**: «Рейтинг» → «Магазин» (у сотрудника Рейтинг в таб-баре); у директора — «Настройки» → «Сотрудники» → «Магазин» и «Команда» → «Магазин». Своей вкладки у магазина нет.
- **Очки выключены** (`points_enabled = false`) — обмен закрыт, сделанные заказы на экране остаются (D-71 §11). Фото наград — `[не построено]` (значок-эмодзи).

## State management

- **TanStack Query v5 — единственный владелец серверного состояния.** Кеш Query = источник optimistic-обновлений поверх outbox: тап пишет в outbox + `setQueryData` мгновенно, эффект и сеть — потом.
- **Zustand — только эфемерное UI**: конвейер ввода (`lib/store/ingest.ts`), состояние записи. Redux/Context-зоопарк запрещён.
- **Realtime — только через единый хук `useRealtimeQuery(queryKey, channelSpec)`**, другие способы подписки запрещены. Внутри: события → `setQueryData`; на `visibilitychange → visible` и `online` — snapshot-рефетч + teardown/resubscribe каналов. Догон пропущенного — **курсор `seq`**: рефетч `where seq > last_seq` (per-company монотонный seq — контракт H/D-39). WebSocket у свёрнутой PWA умирает молча — события за время разрыва иначе потеряны навсегда.
- Пагинация лент: cursor-based (`seq`), страница 30, `useInfiniteQuery`. Виртуализация — только по факту профилирования.
- **DoD каждого realtime-экрана: «свернул на 5 минут → развернул → лента актуальна без pull-to-refresh».**

## Оффлайн-outbox

Background Sync на iOS нет — ретраи живут, только пока приложение открыто/разворачивается.

**Как устроено:** мутации задач (принял / отчёт / приёмка / отказ / отозвать / продлить / переназначить) идут через `postJson` с `networkMode: offlineFirst` — без сети мутация ставится на паузу и доигрывается сама при `online`; повторы только на сетевые ошибки, 6× до 15 с. Параллельно `lib/outbox.ts` держит копию неотправленного в localStorage под его `client_request_id` — POST-мутации и сообщения треда (`kind: "message"`): при старте приложения (`<OutboxReplay>`) и при возврате сети без приостановленных мутаций очередь доигрывается ровно один раз — сервер дедуплицирует по ключу. Состояние сети — `OfflineBanner`: «Нет связи. Отправлю, как появится (N в очереди)» над шапкой. Фото в персистентную очередь не попадают.

**Следующий слой — `[не построено]`:**

- IndexedDB store `outbox`: `{id = client_request_id (uuid), kind: 'voice'|'message'|'photo'|'ack'|'status', payload, blob?, created_at, attempts, next_retry_at, status: 'queued'|'sending'|'failed'}`. `client_request_id` обязателен на всех мутирующих эндпоинтах (идемпотентность — G.3).
- Триггеры отправки: `online`, `visibilitychange`, старт приложения, тап по бейджу.
- **`<OutboxBadge>` «N не отправлено»** (шапка feed/pulse); тап = ретрай. Пока его работу делает `OfflineBanner`.
- Backoff: 5с / 30с / 2м; после 5 попыток — `failed` с явным UI (карточка ошибки, ручной повтор).
- **`client_ts` сохраняется и уходит на сервер** — авто-правила очков («принял ≤10 мин») считают по нему (санити: ≤ server_ts).
- Фото: клиентское сжатие ДО укладки в outbox (~1600px, q0.8) + resumable-загрузка; прогресс на пузыре сообщения; ретрай без повторного выбора файла. Фото 8 МБ на EDGE — главный груз очереди (H.10).
- Карточка/сообщение из outbox — состояние «отправится при связи» (часики). Blob-ы считаются против квоты IDB (~1ГБ iOS) — отправленное чистить.

## Game Feel — каталог эффектов

Game feel — часть продукта, не украшение (эталон тактильности — Duolingo). Построено только то, что играет сам маскот (бросок, `celebrating`, сценки, сны — D-60, D-82); остальной каталог и слой `<EffectsLayer>` — `[не построено]`; когда включать — В-1 («Ждёт владельца»). Замысел: единый слой `<EffectsLayer>` поверх приложения — все снаряды, частицы, цифры; одна точка контроля производительности + глобальный выключатель (prefers-reduced-motion и настройка пользователя).

### Три железных правила
1. **Эффект никогда не блокирует действие.** Данные уходят мгновенно по тапу; анимация играет после, поверх. Тапнул и свернул — действие выполнено. Спектакль — слой поверх логики, не часть её.
2. **Полная версия — только в ключевые моменты.** Серийные действия (разбор 10 отчётов) — укороченные версии 200–300мс. Большой праздник — редко, микрофидбек — постоянно.
3. **Бюджет производительности.** Частицы — свой canvas-эмиттер (~100 строк, НЕ tsParticles — 150КБ); сложное (огонь, конфетти) — `@lottiefiles/dotlottie-web` через `next/dynamic` после first paint, файлы 20–50КБ; остальное — Framer Motion строго на transform/opacity. `hardwareConcurrency ≤4 || deviceMemory ≤2` → полурежим (вдвое меньше частиц, без screen shake). Обязательный тест на Redmi: эффект на 8 fps хуже его отсутствия.

### Эффекты
- **Отправка задачи** `[есть]`: тап по маскоту — бросок (`sending`: замах, карточка улетает из руки, поза держится 1,2 с), пачка долетела — `celebrating` 1,8 с с конфетти (D-60, D-82 §4); при ошибке отправки праздника нет.
- **Стопка** `[есть]`: главное действие — свайпом вверх, тост «Отменить» 4 с (D-60, DESIGN §4).
- **Получение задачи (сотрудник)** `[не построено]`: карточка «вонзается» сверху + screen shake 2–3px + хаптик (Android).
- **Очки** `[не построено]`: начисление — золотые цифры с частицами летят в счётчик, count-up с bounce; снятие — красные цифры падают вниз, глухой хаптик. Разная физика = разная эмоция.
- **Реакция директора** `[не построено]`: эмодзи падает на сообщение, искры при ударе; золотая обводка разгорается.
- **Streak** `[не построено]`: живой огонёк (dotLottie); продление — вспышка; потеря — гаснет с дымком.
- **Магазин** `[не построено]`: обмен = «лут-дроп»: переворот карточки, вспышка, конфетти.
- **Ранги** `[не построено]`: повышение — полноэкранная анимация; вычисляются от суммы point_transactions за период, конфиг в company.settings, отдельной таблицы нет.

Звуков нет (D-27). Пересмотр — после пилота по желанию директора.

работу»): имя не даёт рода, а настоящее время по роду не согласуется.

**Стена v2 (D-96).** Раскладка — чистый вид `components/tv/TvFrame.tsx` на пропсах; данные и appliance-часть — `TvScreen`; песочница `/dev/tv?case=face|clock|team|calendar|calendar-month|calendar-empty|board|board-two|board-pages|board-hidden|focus|focus-empty|visit|wait|in|event|night[&clock=analog][&guest=1]` рисует каждую сцену на фикстурах (скриншоты 1920×1080 и 1280×720 — оттуда). **Карточка сотрудника** (`TvFocus`): инициалы или фото, имя, должность, «Сегодня сдано: N ✓», очки недели; под ними три колонки «Новые → В работе → На проверке» с крупным числом над каждой (по всем открытым делам, `tv_focus().counts`), до трёх карточек дел в колонке, «+ ещё N», тающая полоска времени; правила — `focusCard` в `lib/tv/focus.ts`. **Часы** цифрами или стрелками — `tv_state.clock_style` (`TvAnalogClock`: стрелки крутит CSS с отрицательной задержкой, появляются после гидрации) — в заставке «Часы», в подписи и ночью. **Заставка «Календарь»** (`TvCalendar`, `lib/tv/calendar.ts`, D-98): вид «Неделя» — сверху панель «Сегодня» (лента дня с отрезками и отметкой «сейчас», карточки с крупным временем, «идёт · до …» с прогрессом, «через N мин»), снизу шесть дней с завтрашнего; вид «Месяц» — сетка недель с понедельника, сегодня в акцентной клетке. Вид — `tv_state.calendar_view`, клавиши «Неделя / Месяц» на пульте; данные — `tv_calendar(p_guest, p_days, p_from)` (месяц — 42 дня с понедельника первой недели). **Слой «важно сейчас»** (`TvOverlay`, `lib/tv/overlay.ts`): «К вам посетитель» во всю стену поверх любой сцены (слова секретаря, «ждёт 3 мин», звонок `lib/tv/chime.ts` один раз на визит), «Подождёт» — плашка в углу, «Заходите» на 6 с, мероприятие за 15 минут и на старте; данные — `tv_overlay()`, перечитывается по версии `tv_state`. **Заставка «Доска»** (D-102, `TvBoard`, `lib/tv/board.ts`): название крупно, «N пунктов · M отмечено», пункты с номерами — до 6 одной колонкой крупно, до 14 двумя, дальше страницы по 14, листаются сами раз в 20 с по часам киоска («1 / 2», высота страницы постоянная); отмеченный гаснет с галочкой на своём месте, сказанный меньше минуты назад мягко светится (opacity); рядом с поручённым — «→ Марат» / «→ Марат · сдано». Данные — `tv_board(p_guest)` по версии `tv_state` (+ страховка 30 с); доска живёт до `board_until` (21:00; после 21:00 — 2 часа), истекла — лицо (`sceneOf(state, now)`); ночь её не гасит; гость без «Показать гостю» — часы и «Доска скрыта · гость в кабинете». **Ночь** 21:00–08:00 — только тусклые часы, если на стене нет человека, доски или надписи и директор не разбудил стену с пульта (`tv_state.awake_until`, `awakeUntil`, D-105); **сдвиг против выгорания** — вся композиция на несколько пикселей раз в 10 минут (`burnInShift`).

временем, топ недели и последняя награда (только когда очки включены, `points_enabled`, D-48). У гостя в строке нет ни фамилий,

## Производительность

- **Главная метрика бюджетного Android: cold start от тапа по пушу до интерактивной карточки задачи < 2–3с на Redmi-классе.** Цель измерения: LCP ≤ 2.0с / TBT ≤ 300мс на профиле «4x CPU throttle, Fast 3G». Lighthouse CI (порог на PR) и полевые web-vitals (Vercel Speed Insights) — `[не построено]`. JS-бюджет initial route ≤ 200КБ gz: тяжёлое (dotLottie, EffectsLayer, если появятся) — только dynamic import; Recharts в проекте нет.
- **Голос → карточки на доске Пульса: p50 ≤ 6с / p90 ≤ 10с** (D-43; «<3 сек» физически недостижимо и отменено) с видимым прогрессом — его показывает сам маскот (позы стадий, D-60); стриминг чанков во время записи — `[не построено]` (G.23). Тайминги этапов (upload/stt/parse) — в ai_logs; сквозная «голос → задача у сотрудника» меряется с первого дня.

- Анимации: только transform/opacity (никаких width/height/top); длительности — токены DESIGN §2. AnimatePresence со списками — `mode="popLayout"`. Уважать prefers-reduced-motion. Кнопки срабатывают мгновенно, эффект догоняет.
