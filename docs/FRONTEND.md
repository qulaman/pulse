# FRONTEND.md — PWA, экраны, дизайн-система, ТВ-режим

Спецификация фронтенда Pulse (рабочее название продукта, D-20) — контракт для всех, кто реализует UI: экраны, компоненты, state, оффлайн, производительность. Продукт — коммерческий SaaS; всё описанное клиент-агностично, клиентская специфика живёт в `company.settings`. **Арбитр при противоречиях — `DECISIONS.md`.** Схемы данных — `docs/DATABASE.md`, API — `docs/BACKEND.md`.

## Этапность (D-40, вариант «в») — читать первой

Каждый раздел помечен этапом. Порядок этапов и гейты — `docs/CONCEPT.md` §7 (календаря нет — D-46). Агент НЕ реализует функциональность более позднего этапа, даже если она описана ниже подробно.

- **[ПИЛОТ]** — ядро: голос → /confirm → карточка у сотрудника → Принял/Уточнить/Не могу → отчёт → приёмка директором (кнопками) + Пульс-минимум + подсистема доставки + оффлайн-outbox + онбординг. Без очков, рейтинга, магазина, ТВ и game feel-эффектов.
- **[ПОСЛЕ ПИЛОТА]** — гейт адаптации (этап 4): включается после 2–3 недель подтверждённого ежедневного использования директором: очки, рейтинг, магазин, свайп-приёмка, каталог game feel.
- **[ЭТАП МАСШТАБА]** — этап 5: ТВ-режим, пульт. TTS-сводки — этап «Дальше».

Вёрстка этапа [ПИЛОТ] обязана не мешать более поздним слоям (например, анонимизация для ТВ закладывается в компоненты с первого дня), но код поздних этапов не пишется «авансом».

## Дизайн-принципы [ПИЛОТ]

- **Тёмная тема — основная и единственная в v1.** Дорогой, спокойный вид; статусные цвета горят на тёмном.
- Палитра: фон `#0B0F14` → карточки `#131A22`; один акцент — CSS-переменная `--accent` — токен бренда продукта (палитра и токены — будущий `docs/DESIGN.md`; до него — заглушка `#4FA8FF`, использовать ТОЛЬКО через переменную); статусные green/yellow/red — только для состояний; золотой — только для реакций директора и подсветки нового на ТВ. Никакого цветного шума.
- **Клиентская кастомизация = логотип в шапке + опциональный акцентный цвет из `company.settings`** (D-44), не больше. Фирменный цвет клиента (D-24) — конфиг его инстанса, не основа дизайн-системы.
- Типографика крупная: ключевые числа Пульса читаются на вытянутой руке. Кегль тела ≥16px.
- **Планка качества — уровень Kaspi/Telegram.** Целевой директор — насмотренный пользователь: лаги, дешёвые шрифты, отклик >100мс — заметит. Но насмотренность ≠ желание сложности: ядро остаётся максимально простым, глубина — только вторым слоем по явному тапу. Ни один экран не усложняется «авансом».
- Скелетоны, не спиннеры. Скелетон — контракт: layout каждого экрана фиксируется, чтобы не было layout shift. Экран появляется целиком за счёт одного агрегатного запроса.
- Русский язык UI. Тон — короткий, деловой, без канцелярита. Штрафы — нейтрально-фактически; похвала — эмоционально; задачи — глагол+срок.
- `dvh` вместо `vh`; `viewport-fit=cover` + safe-area-inset для FAB и композера (standalone iOS).
- **Хаптики — прогрессивное улучшение, только Android** (`navigator.vibrate`, паттерны ≤30мс). На iOS веб-API хаптик НЕ СУЩЕСТВУЕТ — компенсация микро-скейлом кнопки. Обёртка `lib/haptics.ts` с no-op на неподдерживающих платформах; прямых вызовов `navigator.vibrate` в компонентах нет.

## PWA [ПИЛОТ]

- **`@serwist/next` — единственный разрешённый SW-фреймворк. `next-pwa` запрещён** (заброшен, ломается на Next 15/App Router).
- **SW пишем свой** на базе serwist (не авто-генерация): кастомные обработчики `push`, `notificationclick` (deep-link по `tag`, например `task:{id}` → открыть/сфокусировать нужный экран), POST-роут Web Share Target, ack-fetch на `/api/push/ack` при показе нотификации.
- Полный `manifest.json`: name/short_name, maskable-иконки, apple-touch-startup-image, `display: standalone`, theme_color, `share_target: {action:'/share-target', method:'POST', enctype:'multipart/form-data', params:{title,text,url}}`.
- **Push-разрешение запрашивается после первого осмысленного действия** (принял первую задачу), не на первом входе. Отказ на iOS необратим без переустановки PWA — после отказа сразу предлагать привязку Telegram, повторно не пилить.
- **Web Share Target** (Android only, установленная PWA): route handler `/app/share-target/route.ts` принимает POST → текст → redirect на /confirm с `source:'shared'`. На iOS фичи нет — не обещать в UI.

## Онбординг [ПИЛОТ]

Чек-лист онбординга — экран продукта, не инструкция на бумаге (`<OnboardingChecklist>`):

1. Детект in-app-браузера (Telegram/WhatsApp WebView) → экран «Открой в Safari/Chrome» ДО всех инструкций (инвайт-ссылку пришлют именно в мессенджер).
2. Установить PWA на главный экран (пошаговый оверлей со скринами под платформу; iOS ≥16.4 — иначе нет push).
3. **Доступ к микрофону — отдельный шаг с тестовой записью** («скажи что-нибудь — послушай себя»), НЕ в боевом флоу: первый «зажал FAB» не должен утыкаться в системный диалог.
4. Push-разрешение (после первого действия, см. выше) + привязка Telegram (deep-link на бота).
5. Выключить оптимизацию батареи (MIUI/Xiaomi — экран с инструкцией).
6. Тестовый пуш «на глазах» → отметка о прохождении чек-листа в БД.

Один экран онбординга сотрудника: «Эфир — для всех, Лента — лично тебе». Кнопка Эфира — «Ознакомился», ленты — «Принял» (лексически разведены осознанно).

## Аудио [ПИЛОТ]

Сердце продукта; ошибка здесь ломает принцип 5 CLAUDE.md («аудио всегда доступно сотруднику»).

- **Матрица записи** — пробовать mimeType по порядку: `audio/mp4` → `audio/webm;codecs=opus` → `audio/webm`. Выбранный mimeType отправляется на бэкенд и **хранится в метаданных файла**. Причина: iOS Safari не пишет и не играет webm/opus; mp4/AAC играет везде.
- **Битрейт — приоритет качества STT: 32–64 kbps.** `audioBitsPerSecond` на iOS игнорируется — любое значение описывать как best-effort, «24kbps» контрактом НЕ является.
- **Запись через MediaRecorder с `timeslice`** — чанки стримятся на сервер во время записи; к отпусканию кнопки аудио уже загружено, остаётся STT+parse. Это главный рычаг метрики скорости (D-43).
- Загрузка аудио — клиентом в Storage по signed URL (лимит Vercel 4.5 МБ; G.8).
- `<AudioPlayer>`: волна из массива пиков, сгенерированного при записи/загрузке (AnalyserNode или сервер) и сохранённого в meta — НЕ `decodeAudioData` на клиенте (фриз на Redmi). Скорость ×1.5.
- **DoD голосового конвейера включает смоук-тест «запись на Android → воспроизведение на iPhone»** (и наоборот).

## FAB — кнопка ввода директора [ПИЛОТ]

Глобальная плавающая кнопка на всех экранах директора. Оба входа (голос и текст) ведут в один парсер и один /confirm.

Техконтракт (walkie-talkie в вебе не работает без этого):
- Pointer Events + `setPointerCapture`; `touch-action: none`; `-webkit-user-select: none`; `-webkit-touch-callout: none`; `contextmenu` → `preventDefault()`.
- **Порог 250мс**: одиночный тап → текстовый ввод («как в мессенджере», над клавиатурой чипы частых исполнителей и пресеты дедлайнов); удержание ≥250мс → запись голоса (живая волна/пульсация вокруг кнопки — директор видит, что его слышат), отпустил → отправка.
- **Свайп вверх при удержании = отмена записи** (стандарт мессенджеров).
- Разрешение микрофона получено заранее на онбординге (см. выше).

Состояния: запись/ввод → «Распознаю…» → карточки на месте (на Пульсе — прямо под лицом, с других экранов — на `/confirm`). При ошибке — «Не расслышал» + повтор; аудио не теряется (лежит в outbox).

**Тихий режим** (свитч в шторке): без звуков и TTS, для встреч. Входящие вопросы сотрудников — быстрые **ответы-чипы** («Да», «Нет», «Позже», «Действуй сам») одним тапом. [ПИЛОТ]

Звуковых эффектов в v1 нет вообще (D-27) — тихий режим глушит только автоплей голосовых и будущий TTS.

## Подтверждение фразы [ПИЛОТ]

**Штатное место подтверждения — сама доска, а не отдельная страница** (D-60, шестое уточнение). Конвейер доигрывает на Пульсе: лицо слушало и разбирало — оно же выкладывает карточки под себя (`ConfirmInline` в нижней полосе), над головой его слова «Понял так: 2 задачи» — без инструкций: о тапе говорит само лицо (состояние `offering`, DESIGN §3). Шарики на это время уходят. **Тап по маскоту = бросок**: если есть что отправлять — пачка летит (лицо играет `sending` и выбрасывает карточку из руки, строка «Отправляю…»; поза держится весь размах 1,2 с, даже если сервер ответил за полсекунды), если у задачи нет исполнителя — открывается «Кому?» первой такой карточки. Под карточками «Отменить» и, вне окна доставки, «отправлю утром · отправить сейчас». Удержание лица на это время выключено: фраза уже в руках.

Страница `/confirm` осталась **запаской**: черновик, с которым директор ушёл на другой экран, ждёт в пилюле `DirectorFab` и открывается там же, где и раньше (шапка «Понял так», `SendBar` «Отправить N из M»). Общее у обоих мест — `ConfirmList` (карточки, «Кому?», дедлайн) и `useSendBatch` (что уходит, какой тост, вопрос смешанной фразы после отправки). Оверлей конвейера на /pulse прогресс не рисует и на /confirm не уводит — доска подтверждает на месте.

Список распознанных сущностей карточками: 📢 объявление / ✅ задача / ➕ очки [ПОСЛЕ ПИЛОТА] / 🔔 напоминание. Контракт данных (единый для фронта и бэка): сущности — `lib/ai/schema.ts` (`Entity`, zod), результат матчинга — `AssigneeMatch` из `lib/matchName.ts`: `entity.assignee: {status:'matched'|'ambiguous'|'unmatched', user_id: string|null, candidates:{user_id, full_name, score}[], flag:'ok'|'check'}`; блокировка сущности — `entity.blocked: 'points_blocked'|'assignee_unmatched'` из `lib/ai/postprocess.ts`.

Правки:
- **Тап по тексту карточки → инлайн-редактирование title** (клавиатура). Обязательно: удалять сущность и переговаривать всё голосовое из-за одной ошибки STT — недопустимо.
- **Кнопка «🎤 переговорить эту сущность»** — перезапись одной карточки без потери остальных.
- Правка суммы очков — тем же паттерном (тап → инлайн). [ПОСЛЕ ПИЛОТА]
- Чип исполнителя → выбор из кандидатов; чип дедлайна → пресеты (сегодня 18:00, завтра 9:00, завтра 13:00, своя дата); свайп сущности влево — удалить.

Доверие и прозрачность:
- Поле с `confidence < 0.8` — жёлтый чип «проверь».
- Выведенный дедлайн показывает `deadline_source_text`: «так понял: „завтра до обеда“». Молчаливых дедлайнов нет; без названного срока — `null`, чип «без срока».
- Нераспознанный исполнитель — **красный чип «Кому?»** (тап → полный список), отправка этой сущности заблокирована, остальные не блокирует: кнопка **«Отправить N из M»**.
- Отложенная доставка вне окна 08:00–21:00 (D-38) — пометка «отправлю утром» + тап «отправить сейчас» (на доске — под карточками, на `/confirm` — в `SendBar`).

**Компактный режим при 5+ сущностях**: свёрнутые однострочные карточки (иконка + исполнитель + суть + дедлайн), тап разворачивает; невалидные подсвечены и подсчитаны; кнопка «Отправить N» — sticky снизу.

**Автоотправки нет никогда.** Для `source='shared'` (Web Share Target) — особенно: подтверждение руками обязательно всегда (защита от prompt injection, D-36).

## Экраны сотрудника [ПИЛОТ]

### Лента (/feed) — стиль мессенджера
Диалог с директором. Карточка задачи: заголовок, дедлайн-чип (красный при просрочке), приоритет, ▶️ плеер оригинального аудио + транскрипт под спойлером. Композер снизу: текст / 📷 фото / 🎤 голосовое — **удержание до 10 секунд с обратным отсчётом, без распознавания** (D-66): уходит только запись, её длина едет в `meta.duration_ms`. Реакция директора — эмодзи с золотой обводкой + push [ПОСЛЕ ПИЛОТА].

### Состояние задачи → набор кнопок карточки (ядро UI сотрудника)

| Статус | Кнопки/состояние карточки |
|---|---|
| `sent` | **Принял / Уточнить / Не могу** (три кнопки — принцип №2, не расширять) |
| `accepted` | **Выполнено** (+ композер всегда доступен) → шторка «приложи результат» (фото/текст/голос) → `pending_review` |
| `pending_review` | без кнопок: «На проверке у директора» |
| `rework` | авто-переход в `accepted` (повторный «Принял» не нужен) + push «Вернул на доработку: [комментарий]» |
| `done` | терминал, пометка ✓ |
| `declined` | у сотрудника — терминал с причиной; у директора карточка в «Требует вас»: **Переназначить** (клон в `sent` новому, старая закрывается со ссылкой) / **Отменить** / **Настоять** (возврат в `sent` с комментарием) |
| `revoked` | пометка «отозвано директором» (D-01) |

- «Уточнить» = сообщение с `meta.is_question` (не статус, D-03); флаг снимается ответом директора.
- **«Не могу» — причины-чипы**: «Это не ко мне» / «Занят срочным» / «Буду позже: [дата]» + свободный текст. Свободное поле без чипов — запрещено (на морозе на стройке никто не печатает).
- **«Выполнено» доступно и в /feed, и в /tasks.**
- `in_progress` в UI v1 не показывается (D-04).
- Статус доставки на карточке — `<DeliveryStatus>`: **отправлено / увидел / принял** (честная семантика Web Push, D-32; «доставлено» не существует). В оффлайне — «отправится при связи» (часики).

### Мои дела (/tasks)
Список активных по срочности, просроченные сверху красным, «без срока» — после дедлайновых. Тап → лента, отскролленная к задаче (загрузка окна вокруг task_id, не скролл истории).

### Профиль
[ПИЛОТ]: имя, привязка Telegram, статус чек-листа онбординга, выход. [ПОСЛЕ ПИЛОТА]: баланс очков крупно, место в рейтинге, streak, история начислений с причинами + кнопка «Вопрос по начислению» (D-14/D-28), прогресс до товара, вход в магазин.

## Пульс (/pulse) — экран директора (D-57 живая доска, D-60 маскот-рычаг и стопка)

Экран при открытии = маскот «Капля» в середине, спит, **если доска спокойна** (есть настроение — показывает его, D-68) (`sleeping`; рычаг: удержал — говорит, тап — просыпается, потянул вниз — текст); подсказка жестов — внизу над таб-баром, служебные строки — под строкой ассистента после тапа. Тап будит маскота, он говорит сводку, и вокруг него кружат три шарика (`OrbitBalls`: «Задачи» с числом просрочек/отказов/приёмки и цветом худшей дорожки, «Сообщения» с числом открытых вопросов, «Эфир» с числом объявлений). Тап по шарику открывает панель под рядом шариков: «Задачи» и «Сообщения» — `CardDeck` со всеми жестами (сообщения отдельной стопкой из любых дорожек, без карточки «В работе»), «Эфир» — объявления с «Удалить» у директора (шторка-подтверждение, RLS `announcements_delete`, отметки уходят каскадом); тап по активному шарику складывает панель, тап по маскоту из панели возвращает к шарикам, из шариков — усыпляет. **Сообщения (D-61)** = задачи, где последнее настоящее сообщение треда — от исполнителя и выше курсора прочтения директора (`task_reads`), плюс открытые вопросы; на карточке — слова сообщения и чипы «Прочитал» / «Ответить ›» (для вопроса — быстрые ответы); открытие треда двигает курсор; новое сообщение — мысль маскота «Марат пишет по «…»: «…»». **Эфир — второй источник новостей** (`lib/pulse/ether.ts`, `describeEther`): своё объявление возвращается квитанцией «Объявление ушло всем: «…»», чужое — от имени автора, каждое «Ознакомился» — мыслью «Марат в курсе объявления «…»» (несколько разом — «ознакомились ещё N»); глаголы без рода, как и в задачах. Мысль про Эфир по тапу не открывает тред (за ней нет задачи). **Настроение лица — барометр доски** (D-68, уточнён D-70): срок в пределах часа или просрочка, поручение висит непринятым полчаса, непрочитанное сообщение или открытый вопрос — любая из трёх тревог даёт одно лицо `alert` («насторожен»); негативных состояний у директора нет. Иначе прежние «спокоен» (есть что требует директора) и «доволен». Считает `lib/pulse/mood.ts`; мысль о событии и речь перебивают настроение, спящее лицо его не показывает. Экран один на любой ширине — широкое окно лишь центрирует его (владелец, 2026-09-17; до этого с 640 px показывалась доска `LiveBoard`). Отдельной кнопки микрофона нет. Состояние живёт на карточках, речь живёт в моменте (одна фраза о том, что только что случилось). Транскрипта-диалога нет: предложения хороши для изменений, карточки — для состояния (D-57 пересматривает D-49 в этой части). Жесты — DESIGN.md §4.

- **Данные — один запрос и две подписки** (`usePulseBoard`, `lib/tasks/queries.ts`): `tasks` в статусах работы/приёмки/отказа с вложенными сообщениями-вопросами и причинами отказа (`task_messages` с фильтром по `meta`), RLS компании. Событие `tasks` по Realtime **патчит строку из payload** (статус, срок, заголовок) — без запроса; только незнакомая строка (новая задача) или новый исполнитель просят один склеенный (150 мс) рефетч. Событие `task_messages` кладёт вопрос/причину или закрывает вопрос по его `answered_at`. Чистая модель — `lib/pulse/board.ts` (дорожки, редьюсеры `applyTaskChange`/`applyMessage`, фразы `describeChange`, `openingLine`; unit-тесты). Таб-бейдж «Пульс» и отметки вопросов в «Задачах» читают тот же кэш (`useDirectorInbox` — производная).

Тап по тексту раскрывает на месте полный `TaskCard` директора. Смена статуса = плитка перекрашивается (200 мс) и переезжает в свою дорожку (Framer `layout="position"`, `AnimatePresence popLayout`); закрытая задача прощается 1,4 с (золото — принято, серое — отозвана) и уходит; «призрак» прощания не зависит от кэша (рефетч после собственного «Принято» его не обрывает). Сводная полоса счётчиков над дорожками. Пропсы `readOnly` и `anonymized` заложены для `/tv` (этап 5) — та же доска, без действий и без имён.
- **Стопка** (`components/pulse/CardDeck.tsx`, телефон, открывается из шарика «Задачи» или «Сообщения»): карточки дорожек в порядке D-05, верхняя тянется пальцем: влево/вправо — листать, вверх — главное действие дорожки с тостом «Отменить» 4 с (отложенная отправка), вниз — отложить в конец, тап — полная `TaskCard` в шторке, долгое нажатие — меню (открыть / переназначить / отозвать / удалить). Последняя карточка «В работе · N» — ссылка в «Задачи». В DOM три карточки.
- **Ассистент** (`components/pulse/Assistant.tsx`, `MascotLever.tsx`, `ThoughtBubble.tsx`, `useSpeech.ts`): маскот 128 px как рычаг; сводка — строкой под ним (речь), изменение на доске — облачком мысли над ним, маскот просыпается удивлённым и через 9 с засыпает; `useSpeech` помечает вступительную строку (`opening`), страница разводит речь и мысли. При открытии — приветствие по времени Aqtobe и вердикт («1 просрочка, 2 на приёмке.») или «Пока тихо. N задач в работе, ближайший срок …»; затем каждое изменение доски заменяет строку фразой о нём: «Марат: задача «…» принята в работу», «… сдана, ждёт приёмки», «Марат не может «…»: занят срочным», «Марат спрашивает по «…»: «…»», «Принято: «…»». Глаголы согласуются с «задачей», имена в именительном. Без печати по буквам: строка появляется сразу, рот маскота двигается ~1,2 с (`speaking`). Тап по маскоту повторяет сводку. Состояние маскота: думает — грузится; говорит — 1,2 с после новой строки; спокоен — есть дорожки «требует вас»; доволен — доска сверху пуста.

Конвейер играет **сам маскот экрана**: `MascotLever` берёт позу и подпись стадии из `lib/voice/stages.ts` (`recording → listening`, `uploading → saving`, `transcribing`, `parsing`, `sending → sending`), кормит лицо уровнем микрофона и печатает счётчик записи в узел, не перерисовывая доску. `IngestOverlay` на /pulse получает `progress={false}` — прогресс там был бы вторым маскотом поверх первого; карточка ошибки остаётся оверлеем на всех экранах (D-60, пятое уточнение).
- **Вопросы директора** (владелец, 2026-09-11): фраза, которую парсер разобрал только как `query`, не открывает /confirm — конвейер переходит в стадию `question`, оверлей ведёт на Пульс: справа слова директора, под маскотом ответ (строки сразу, без печати) и «Закрыть»; ответ держится, пока директор не спросит снова, не тапнет маскота или не закроет — живые события его не перебивают (доска показывает их сама). Ответы детерминированные, из данных (`lib/pulse/answers.ts`, unit-тесты): просрочки / кто не отчитался, приёмка, открытые вопросы сотрудников, человек (имя или алиас в любом падеже), тема (слово из вопроса в заголовке задачи), общая картина. Непонятый вопрос — «Пока отвечаю только про задачи и людей…» и кнопки «Сделать задачей» / «Закрыть». Вопрос в смешанной фразе остаётся карточкой на /confirm и после отправки задаётся ассистенту. Claude-ассистент этапа 3 встанет в этот же слот. Быстрые вопросы — чипы под строкой.

Пульс под шторкой не размонтируется: стопка, шарики и состояние маскота остаются те же, `usePulseBoard` не перезапрашивается — открытие стоит один запрос треда (`useTaskMessages` с `enabled`). Карточка в панели «Сообщения» показывает хвост до трёх последних реплик (`ThreadTail`, запрос только у карточки впереди) и строку ответа: поле, микрофон с удержанием (`Composer` в `inline`) и чип «Прочитал». Границы чата — D-64 §6: переписка живёт только внутри задачи, личных и групповых чатов нет, «печатает» не делаем, реакции — после гейта D-40.

### Действия директора на карточке (владелец, 2026-09-11)
Открытая задача: «Продлить» (шторка сроков с пресетами и календарём; «Без срока» снимает срок), «Переназначить» (выбор человека из ростера, задача уходит новому как новая, у прежнего закрывается с пометкой), «Отозвать». Отказ («Не могу»): «Настоять / Переназначить / Отменить». Приёмка: «Принято / Доработка». Изменения видны в хронологии треда системными строками.

### /confirm — нет тупиков (владелец, 2026-09-11)
Главная кнопка панели всегда нажимается: «Отправить N из M» когда есть что слать; «Указать, кому» когда все задачи заблокированы на исполнителе (открывает первую); «Закрыть» когда отправлять нечего. В шапке «Понял так: …» — явный «Закрыть» (44 px), черновик при этом сбрасывается. Ничего не разобрано (пустой ответ парсера или «не берусь») — единый экран «Не разобрал. Услышал так: „…“» с кнопками «Исправить текст» (шторка с транскриптом → повторный разбор под новым `client_request_id`, иначе идемпотентность вернёт тот же пустой результат), «Сделать задачей», «Закрыть»; окно ошибки оверлея для этих случаев больше не показывается.

### Задачи (/sent)
Всё, что директор раздал, новейшие сверху, фильтры-чипы «В работе / На приёмке / Закрытые / Все». Одна задача = капсула (`TaskCapsule`): точка статуса слева (просрочка — красная), заголовок в одну строку, под ним три факта с иконками — кому (имя), срок («до завтра 13:00», красным при просрочке, «без срока»), когда дали («дали сегодня 9:02»); справа короткий статус строчными. Тап → тред задачи. Кнопки директора живут в треде и в репликах Пульса, не в списке.

### Рейтинг (/rating)
Периоды «Неделя / Месяц / Всё время» (переключение держит прошлые строки, без повторного скелетона). Подиум топ-3 (второй слева, первый в центре и выше, третий справа; кольца золото/серебро/бронза, маскот «доволен» у лидера) — только для людей с очками. Сводка периода: «очков за период / с очками / в срок». Сотруднику — карточка «Вы на N месте · Имя впереди на X» (или «вы лидер»). Список: ранг, аватар с медальным кольцом у топ-3, имя, динамика ↑↓ к прошлому периоду, «% в срок» или «без закрытых», очки; у директора «+» → `AwardSheet`. Тап по строке или по фигуре подиума → `PointsSheet`: место, очки за период и всего, список «за что и когда» (видит сам человек и директор; чужие — только сводка), кнопка «Поощрить». Очки выключены — баннер с ссылкой в Настройки (директору). Данные — `fn_rating` (`useRating`), `usePointHistory`.

### Команда (/people)
Шапка: «N на месте · M отсутствуют · K задач в работе · X просроч.» и «+ Добавить». Сетка «Сейчас»: аватарки с цветной точкой загрузки (задача без дедлайна = green) и бейджем активных задач, тап → карточка сотрудника с «Дать задачу этому человеку». Ниже — ссылка «Рейтинг» и полный список: поиск по имени, должности и алиасу из речи; фильтры «Все / На месте / Отсутствуют / Перегружены (просрочка или ≥4 задач) / Свободны»; сортировка «имя / загрузка / очки»; группы «Руководство / Сотрудники / Экраны»; в строке — точка загрузки, «3 задачи · 1 просроч.» или «свободен», баланс очков (когда включены), чип доступности; уволенные свёрнуты внизу. Данные — `useTeamLoads` (общая свёртка открытых задач по исполнителю, realtime по `tasks`) и `useTeamBalances`. В таб-баре директора — вкладка «Команда».

### Свайп-приёмка [ПОСЛЕ ПИЛОТА]
Тап по стопке → режим свайпов: колода, верхняя карта приподнята, прогресс «3 из 7». **После каждого свайпа — undo-тост 5 сек** («Принято ✓ — Отменить»); отмена = компенсирующие записи (статус назад, сторнирующая point_transaction). Таблица жестов по типам стопок:

|---|---|---|---|
| Отчёты (приёмка) | Принято | Доработка (голос. комментарий) | Принято + 🔥 + очки (значение из company.settings) |
| Вопросы | Ответы-чипы (Да/Нет/Позже/Действуй сам) | Ответить голосом | — |
| Просрочки | Продлить дедлайн (пресеты) | Голосовое сотруднику | — |
| Заявки магазина | Approve | Cancel с причиной | — |

Комбо-счётчик «Разобрано N подряд» — не делать (UX-ревью).

## Лента (/feed) — экран сотрудника (D-62: тот же маскот)

Экран при открытии = маскот в середине (без микрофона: сотрудник говорит внутри задачи, не лицу); спит, только если принимать нечего — иначе **зовёт** ещё до первого тапа (D-69). Тап будит его: строка «Добрый день, Марат. 2 новые задачи, 1 на доработке.» и три кружащих шарика — **«Дела»** (все открытые задачи сотрудника: `sent`, `rework`, `accepted`, `in_progress`; число — их сумма; жёлтый, когда есть что принять или доработать, красный при просрочке), **«Сообщения»** (задачи, где последнее настоящее сообщение — не моё и выше моего курсора `task_reads`), **«Эфир»** (объявления без моего «Ознакомился»). Панели: «Дела» — карточки сотрудника с тремя кнопками (принцип 2): сначала принять/доработать, затем в работе, ниже приглушённо «На проверке у директора», ссылка «Все дела ›» на /tasks; «Сообщения» — карточка треда: хвост последних реплик (`ThreadTail`), «Прочитал», «Открыть переписку ›» и строка ответа, где **микрофон стоит первым**, а поле вторым (сотрудник отвечает со стройки, D-64 §5); тап по карточке открывает тред шторкой поверх Ленты (`ThreadSheet`), маскот и шарики под ней остаются как были; «Эфир» — объявления с «Ознакомился». Пока висит непринятая задача или возвращённая на доработку, лицо **зовёт** (`calling`, D-69: наклон, два подскока, «!» над головой) — и перестаёт, как только человек нажал «Принял». Дальше по весу: свой срок в пределах часа или просрочка — `panicking`, непрочитанное слово директора — `nervous` (D-70: чувства живут на стороне сотрудника). Изменение со стороны директора — мысль над головой (`lib/pulse/employee.ts`: «Новая задача: «…»», «Директор вернул «…» на доработку», «Директор принял «…»», «Директор отозвал «…»», «Директор пишет по «…»: «…»»), маскот просыпается удивлённым; новое объявление в Эфире — тоже мысль («Новое объявление: «…»», `describeEtherForEmployee`), а чужие «Ознакомился» сотруднику не зачитываются. Данные — тот же `usePulseBoard` (RLS сужает доску до своих задач), голос — `useSpeechWith` с `employeeOpening`/`describeForEmployeeAll`. Push и установка — служебными строками после тапа; подсказка «тап — дела, сообщения, эфир» внизу.

## Эфир (/ether)

## Магазин (/shop) [СДЕЛАН, D-71]

Экран открыт **любой вошедшей роли** и говорит каждой своё.

- **Сотрудник**: карточка баланса (точная `SUM(point_transactions)`, а не сумма последних 50 строк истории — цена сверяется с настоящим числом), витрина, «Мои заказы». В карточке товара — эмодзи (фото витрины пока нет), название, одна строка описания и цена. Кнопка «Обменять» есть только тогда, когда очков хватает; иначе полоска накопления и «Ещё N очков» — цель, а не запрет. Свой заказ в `pending` сотрудник отменяет сам (D-37), очки возвращаются ровно на сумму холда.
- **Директор**: не витрина, а **пульт** (D-71 §12–14). Экран отвечает по порядку вопросов руководителя. (1) **Герой** — чем магазин жил месяц: крупно число выданных наград (смысл магазина — не остатки на складе, а то, сколько людей что-то унесли), лицо ассистента, под чертой два факта: очки на руках у команды и сколько заказов ждёт. Статичное золотое сияние в углу карточки — «дорого» без анимации теней и фильтров (перф-контракт DESIGN §2); золото здесь уместно, это экран наград. (2) **«Выдать»** — секция есть, только когда есть что выдавать: аватар, имя, награда и «ждёт 3 часа»; ровно **одна крупная кнопка «Выдал»** и мелкая ссылка «Отменить». Промежуточного «Подтвердить» у директора нет — это ярус завхоза. (3) **«Награды»** — сетка плиток 2×N: значок на золотом ореоле, название, ценник-ярлык и строка жизни «взяли 3 раза» / «пока не брали»; состояние склада («скрыта», «нет на складе», «3 шт.») — ярлыком в углу. Последняя плитка — пунктирная «Добавить награду». Тап открывает лист-редактор с **живым превью** карточки сотрудника, чипами цен, чипом «Сколько угодно», переключателем «Показывать в магазине» и «Удалить награду»; сохранение — upsert по заранее выданному id (принцип 7), удаление возможно только у награды без заказов. (4) **«Кому что досталось»** — три последние выдачи с именами: магазин как событие, а не как склад. (5) **«Очки команды»** — два факта (роздано за месяц / унесено в магазин) и трое, кто ближе всех к своей награде («ещё 385 до „День отгула“»); построчная история — за тапом «Вся история очков», в шторке. (6) Ссылка **«Поощрить очками»** на Рейтинг: начисляют очки там (D-48). Появление блоков — лесенка 40 мс, только transform/opacity, под `prefers-reduced-motion` блоки просто стоят. Вход: Настройки → Магазин.
- **Завхоз**: витрина со своим балансом (он тоже копит очки) плюс очередь выдачи; свой заказ он не проводит — это делает директор.
- **Realtime**: `shop_items` и `orders` в публикации, баланс переспрашивается на события `point_transactions` — заказ, выдача и отмена доезжают на открытый экран без перезагрузки.
- **Входы**: «Рейтинг» → «Магазин» (у сотрудника Рейтинг в таб-баре) и «Команда» → «Магазин» у директора. Таб-бар не трогали: четыре вкладки на роль (D-59).
- **Не сделано намеренно**: администрирование витрины (цены, новые товары, остатки) и фото товаров — правится в БД, экрана пока нет.

## State management [ПИЛОТ]

- **TanStack Query v5 — единственный владелец серверного состояния.** Кеш Query = источник optimistic-обновлений поверх outbox: тап пишет в outbox + `setQueryData` мгновенно, эффект и сеть — потом.
- **Zustand — только эфемерное UI**: состояние записи, очередь EffectsLayer, тихий режим. Redux/Context-зоопарк запрещён.
- **Realtime — только через единый хук `useRealtimeQuery(queryKey, channelSpec)`**, другие способы подписки запрещены. Внутри: события → `setQueryData`; на `visibilitychange → visible` и `online` — snapshot-рефетч + teardown/resubscribe каналов. Догон пропущенного — **курсор `seq`**: рефетч `where seq > last_seq` (per-company монотонный seq — контракт H/D-39). WebSocket у свёрнутой PWA умирает молча — события за время разрыва иначе потеряны навсегда.
- Пагинация лент: cursor-based (`seq`), страница 30, `useInfiniteQuery`. Виртуализация — только по факту профилирования.
- **DoD каждого realtime-экрана: «свернул на 5 минут → развернул → лента актуальна без pull-to-refresh».**

## Оффлайн-outbox [ПИЛОТ]

Background Sync на iOS нет — ретраи живут, только пока приложение открыто/разворачивается.

**Сделано (2026-09-11, первый слой):** мутации задач (принял / отчёт / приёмка / отказ / отозвать / продлить / переназначить) идут через `postJson` с `networkMode: offlineFirst` — без сети мутация ставится на паузу и доигрывается сама при `online`; повторы только на сетевые ошибки, 6× до 15 с. Параллельно `lib/outbox.ts` держит копию неотправленного POST в localStorage под его `client_request_id`: при старте приложения (`<OutboxReplay>`) и при возврате сети без приостановленных мутаций очередь доигрывается ровно один раз — сервер дедуплицирует по ключу. Строка «Нет связи. Отправлю, как появится (N в очереди)» над шапкой. Сообщения и фото (прямые insert в supabase-js) в персистентную очередь пока не попадают — следующий слой ниже.

- IndexedDB store `outbox`: `{id = client_request_id (uuid), kind: 'voice'|'message'|'photo'|'ack'|'status', payload, blob?, created_at, attempts, next_retry_at, status: 'queued'|'sending'|'failed'}`. `client_request_id` обязателен на всех мутирующих эндпоинтах (идемпотентность — G.3).
- Триггеры отправки: `online`, `visibilitychange`, старт приложения, тап по бейджу.
- **`<OutboxBadge>` «N не отправлено» — обязательный элемент UI** (шапка feed/pulse); тап = ретрай. Без него очередь невидима и не вызывает доверия.
- Backoff: 5с / 30с / 2м; после 5 попыток — `failed` с явным UI (карточка ошибки, ручной повтор).
- **`client_ts` сохраняется и уходит на сервер** — авто-правила очков («принял ≤10 мин») считают по нему (санити: ≤ server_ts).
- Фото: клиентское сжатие ДО укладки в outbox (~1600px, q0.8) + resumable-загрузка; прогресс на пузыре сообщения; ретрай без повторного выбора файла. Фото 8 МБ на EDGE — главный груз очереди (H.10).
- Карточка/сообщение из outbox — состояние «отправится при связи» (часики). Blob-ы считаются против квоты IDB (~1ГБ iOS) — отправленное чистить.

## Game Feel [ПОСЛЕ ПИЛОТА] — каталог эффектов

Game feel — часть продукта, не украшение (эталон тактильности — Duolingo), но включается ТОЛЬКО после пилота (D-40в). Единый слой `<EffectsLayer>` поверх приложения: все снаряды, частицы, цифры. Одна точка контроля производительности + глобальный выключатель (prefers-reduced-motion и настройка пользователя).

### Три железных правила
1. **Эффект никогда не блокирует действие.** Данные уходят мгновенно по тапу; анимация играет после, поверх. Тапнул и свернул — действие выполнено. Спектакль — слой поверх логики, не часть её.
2. **Полная версия — только в ключевые моменты.** Серийные действия (разбор 10 отчётов) — укороченные версии 200–300мс. Большой праздник — редко, микрофидбек — постоянно.
3. **Бюджет производительности.** Частицы — свой canvas-эмиттер (~100 строк, НЕ tsParticles — 150КБ); сложное (огонь, конфетти) — `@lottiefiles/dotlottie-web` через `next/dynamic` после first paint, файлы 20–50КБ; остальное — Framer Motion строго на transform/opacity. `hardwareConcurrency ≤4 || deviceMemory ≤2` → полурежим (вдвое меньше частиц, без screen shake). Обязательный тест на Redmi: эффект на 8 fps хуже его отсутствия.

### Эффекты
- **Отправка задачи («стрела»)**: кнопка сжимается → карточка сворачивается в снаряд → летит по дуге к аватарке исполнителя → удар: вздрагивание, вспышка, кольцо, хаптик. Контракт EffectsLayer: `fireProjectile({fromRect, toRect?})`, цель — `data-effect-target="user:{id}"` через getBoundingClientRect; **цели нет во вьюпорте → короткая версия** (улёт за верхний край, 300мс) + тост «5 отправлено: Марат, Ерлан…». Веер — интервал 100мс. Полная версия 700–900мс.
- **Получение задачи (сотрудник)**: карточка «вонзается» сверху + screen shake 2–3px + хаптик (Android).
- **Очки**: начисление — золотые цифры с частицами летят в счётчик, count-up с bounce; снятие — красные цифры падают вниз, глухой хаптик. Разная физика = разная эмоция.
- **Реакция директора**: эмодзи падает на сообщение, искры при ударе; золотая обводка разгорается.
- **Свайп-приёмка**: вправо — улёт с зелёным шлейфом; вверх с 🔥 — сгорает в частицах.
- **Streak**: живой огонёк (dotLottie); продление — вспышка; потеря — гаснет с дымком.
- **Магазин**: обмен = «лут-дроп»: переворот карточки, вспышка, конфетти.
- **Ранги**: повышение — полноэкранная анимация; вычисляются от суммы point_transactions за период, конфиг в company.settings, отдельной таблицы нет.
- **ТВ**: те же события той же стрелой — публичный game feel [ЭТАП МАСШТАБА].

Звуков нет (D-27). Пересмотр — после пилота по желанию директора.

### Маскот (D-45)

Персонаж-ассистент — простая геометрическая фигура, «эмоциональный телеграф директора»: передаёт сотруднику состояние директора по фактам системы (доволен / спокоен / ждёт / встревожен / недоволен). Негативные состояния — только приватно в личном канале, тон не карикатурный и не унизительный; при штрафе UI сухой, маскот нейтрален; никогда не блокирует действие.
Контракт производительности: один SVG/canvas-элемент; анимация только transform/opacity/цвет, анимируемые filter/box-shadow запрещены; «дыхание» в покое — чистая CSS-анимация; пауза вне экрана / при свёрнутой вкладке / prefers-reduced-motion; вес всех состояний ≤5 КБ.
Этапность: директору — нейтральные состояния в диалоговых моментах (запись/распознавание/подтверждение) с MVP [ПИЛОТ]; эмоциональный телеграф сотрудникам — по гейту адаптации [ПОСЛЕ ПИЛОТА]. Детали, позы и имя персонажа — DECISIONS.md D-45 и будущий `docs/DESIGN.md`.

**Маскот на стене.** Лицо — то же «Капля», крупно и с репликой о последнем событии; состояний ровно четыре и

временем, топ недели и последняя награда (только когда очки включены, D-40). У гостя в строке нет ни фамилий,

Состав маски по D-33 в редакции рекомендации: без фамилий (только имя), без очков и без заголовков поручений (названия контрагентов).
- **Appliance-чеклист**: автозапуск `chrome --kiosk`; ночной `location.reload()` в 04:00 + принудительный reload по `tv_state.reload_requested_at` с пульта (деплой не ждёт ночи; киоск сравнивает отметку с временем своей загрузки — `useRemoteReload`); квитанция стены — `tv_heartbeat(applied_version)` раз в минуту и на каждое применённое состояние (`useHeartbeat`, только роль `tv`); watchdog WebSocket → реконнект + бейдж «оффлайн» в углу; `cursor: none`; запрет screensaver/сна ОС. Лимит DOM ленты, все анимации transform/opacity (24/7 без утечек).

## Компонентная база

`<PulseMark>` (марка: линия кардиомонитора + слово), `<Mascot state size>` («Капля», D-45: calm/listening/thinking/speaking/happy и сцены конвейера, CSS-дыхание), `<VoiceButton>` (FAB, запись+волна, подсказка «удержи — говори · тап — текст»), `<TaskCard>` (варианты director/employee/tv; пропс `anonymized`), `<EventItem>`, `<StatusChip>`, `<PointsBadge>`, `<SwipeDeck>`, **`<VoicePlayer>`** (свой плеер вместо `<audio controls>`: волна из 28 баров по 3 px, детерминированная по id записи; пройденное закрашивается непрерывно (две волны, движущийся `clip-path` в обход React), при проигрывании по ней катится один гребень (отрицательная задержка на один цикл по всей дорожке, амплитуда 0.88–1.10), тап по волне перематывает, справа остаток; подписанный URL берётся по первому тапу. Один на голосовое в треде и «Оригинал голосового» директора, D-66; ускорения ×1.5 нет — сообщение и так не длиннее 10 секунд), `<CountUpNumber>`, `<RatingList>`, `<EmployeeDot>`, **`<DeliveryStatus>`** (отправлено/увидел/принял + часики оффлайна), **`<OutboxBadge>`** («N не отправлено», тап=ретрай), **`<OnboardingChecklist>`** (экран чек-листа с отметками в БД), `<EffectsLayer>` [ПОСЛЕ ПИЛОТА]. Всё в /components; Storybook не нужен — каждому компоненту страница-песочница в /app/dev (закрыта notFound() в проде). Сквозная проверка в реальном браузере — `pnpm smoke:ui` (Playwright поверх системного Chrome, скриншоты; с `FAKE_MIC_WAV` проверяет и голосовой путь через фальшивый микрофон), `pnpm smoke:board` (живая доска Пульса: задержка «событие → плитка»), `pnpm smoke:jank` (сдвиги вёрстки).

## Производительность [ПИЛОТ]

- **Главная метрика бюджетного Android: cold start от тапа по пушу до интерактивной карточки задачи < 2–3с на Redmi-классе.** Измерение: LCP ≤ 2.0с / TBT ≤ 300мс на профиле «4x CPU throttle, Fast 3G» в Lighthouse CI (порог на PR) + полевые web-vitals (Vercel Speed Insights). JS-бюджет initial route ≤ 200КБ gz: Recharts, dotLottie, EffectsLayer, AudioPlayer — только dynamic import.
- **Голос → интерактивный /confirm: p50 ≤ 6с / p90 ≤ 10с** (D-43; «<3 сек» физически недостижимо и отменено) с видимым прогрессом: стриминг чанков во время записи + скелетон «материализации». Тайминги этапов (upload/stt/parse/render) — в ai_logs; сквозная «голос → задача у сотрудника» меряется с первого дня.
- **Джанк-бюджет: сначала «ничего не дёргается», потом спецэффекты.** Пилот без game feel обязан быть идеально плавным.
- Анимации: только transform/opacity (никаких width/height/top). Длительности: микрофидбек 100–150мс, переходы экранов ≤150мс (мгновенность важнее красоты у сотрудника), эффекты Game Feel 200–900мс по каталогу, ТВ 400–600мс. AnimatePresence со списками — `mode="popLayout"`. Уважать prefers-reduced-motion. Кнопки срабатывают мгновенно, эффект догоняет.
- Изображения через next/image; фото-отчёты — превью из Storage transform (width=400), полноразмер по тапу.
- Пульс = 1 запрос (`usePulseBoard`: задачи с вложенными вопросами/причинами) + 2 подписки, события патчат кэш из payload. Никаких водопадов; `v_pulse_summary` — только если запрос станет медленным.
