# TESTING.md — проверки, смоуки, Definition of Done

Как проверяется Pulse: уровни и команды, pgTAP и unit-тесты, evals парсера, смоуки, телефоны, Definition of Done. Для того, кто сдаёт работу или ищет, чем проверить изменение. Среды — `docs/SETUP.md`, СТТ-гейт — `docs/STT_GATE.md`, корпус парсера по существу — `docs/AI.md`.

## Карта

| Что | Где |
|---|---|
| Unit | рядом с кодом в `lib/`, в `tests/`; `vitest.config.ts` |
| pgTAP | `supabase/tests/`, фикстуры `supabase/seed.sql` |
| Evals | `tests/ai/eval.ts`, `tests/ai/parser_evals.jsonl`, `lib/ai/evals/`, `lib/ai/rules.ts`, `tests/ai/results/` |
| СТТ-гейт | `tests/stt/run.mjs`, `tests/stt/corpus.jsonl`, `tests/stt/RECORDING.md` |
| Смоуки | `scripts/`, по файлу на команду; `scripts/desk-smoke/` |

## Правила

- CI нет: всё запускается руками, итог пишется в WORKLOG (D-19).
- Новая таблица, бакет или RPC — политики в той же миграции и негативный pgTAP, в том числе «компания A не видит компанию B» (D-134); «видит своё» мало.
- Промпт парсера, схема сущностей, few-shot — только с прогоном `pnpm eval:parser` выше гейтов (§4).
- Изменение, с которым прежняя сборка работать не сможет (тело роута, аргументы RPC, форма читаемой таблицы, формат офлайн-очереди), поднимает `COMPAT` в `lib/version.ts` (D-115).
- Dev-база общая с пилотом: пишущий смоук шлёт настоящие пуши. Часть смоуков сама ищет свежие `ai_logs` и без `FORCE=1` не идёт.

## 1. Уровни и команды

| Уровень | Команда | Когда |
|---|---|---|
| Типы, линт | `pnpm typecheck`, `pnpm lint` | всегда |
| Unit | `pnpm test` | всегда (§3) |
| pgTAP | `pnpm test:rls` | миграция, политика, RPC (§2) |
| Evals | `pnpm eval:parser` | промпт, схема, few-shot (§4) |

## 2. pgTAP

`pnpm test:rls` — `supabase test db --linked`: файлы `supabase/tests/` идут в dev-проекте, каждый внутри `begin … rollback`. CLI запускает их в контейнере — нужен Docker Desktop; без него в WORKLOG пишется, что pgTAP не прогнан. Расширение ставит сид.

Что держит набор (номера файлов):

- видимость: задачи по ролям и поддереву менеджера, защищённые поля профиля, киоск, права секретаря, телефон и аватар, занятость директора (001, 002, 005, 026, 053, 054);
- жизнь задачи: матрица переходов, `transition_task`, отзыв, «Настоять», продление, передача, удаление, отчёт, «Отправить сейчас», повторы, проверка исполнителя (003, 004, 007, 008, 011, 013, 017, 037, 038, 040, 047, 049);
- голос: `confirm_voice_batch` — идемпотентность, копии, тихие часы, минус; бакет `voice`, срок хранения (006, 043, 051);
- очки: флаг, `award_points`, рейтинг, баланс как сумма журнала, авто-правила, реакции (009, 039, 041);
- доставка: outbox, квитанции, захват строк, тексты, правила директора, сигналы, самоочистка (010, 012, 016, 029–032, 036);
- прочтения (014, 015), заметки и доски (018, 025, 034, 044–046), стена (019, 022, 024, 027, 033, 035), календарь (020, 023), заявки и посетители (021–024, 028, 032), вход и сессии (042, 043), отчёт (048, 050), консоль (052), флаг `dev_tools` (055).

Пробел. Сид заводит одну компанию; вторую создают только 015, 042 и 044–055, и «компания A не видит компанию B» проверено лишь для того, что трогают они (D-134 п. 6). Магазин (`create_shop_order`, hold-final) и бакет `photos` негативных кейсов не имеют. Файлы на фикстурах сида зависят от dev: люди сида там живые, их роли меняются; новый файл заводит свои фикстуры внутри отката, как 049–055.

## 3. Unit

`pnpm test` — `vitest run` по `lib/` и `tests/`, только файлы .test.ts (.test.tsx не подхватится), среда node без DOM: компоненты проверяются рендером в строку (`tests/mascot-anim.test.ts`). Без сети и базы.

- Разбор: имена (`lib/matchName.test.ts`: падежи, тёзки — кандидаты, «не распознан» вместо догадки), время Asia/Aqtobe, схема и промпт по видам, постобработка, STT с повтором и запасным провайдером, цены, скоринг evals.
- Телефон: один `client_request_id` на фразу (`lib/store/ingest.test.ts`), сохранённые фразы (`lib/voice/`), офлайн-снимок, слияние realtime, окно «Отменить» (`lib/tasks/grace.test.ts`), обновление версии (`lib/version.test.ts`).
- Пуши, стена, доски, календарь, заявки, люди, десктоп, консоль, `lib/env.public.ts` против схемы.

Матрица статусов, очки и права ролей — уровень базы (§2).

## 4. Evals парсера

Корпус — `tests/ai/parser_evals.jsonl`, строка на случай:

```json
{"id":"…","source":"voice","transcript":"…","frozen_now":"2026-08-13T16:32:00+05:00","expected":{"entities":[{"kind":"task","assignee_id":"u-003","deadline_iso":"…"}]}}
```

`frozen_now` обязателен: даты считаются от него. `assignee_id` — id ростера `tests/stt/roster.json`; прогон подменяет их на uuid, как в настоящем ростере (`--demo-ids` — оставить).

Скоринг (`lib/ai/evals/score.ts`): ожидаемая сущность парится с предсказанной того же вида; точность исполнителя — доля верных `assignee_id`, entity F1 — по парам с верным исполнителем, срок верен в пределах 30 минут. Гейты — `PARSER_GATES` в `lib/ai/rules.ts`: исполнитель ≥ 97%, F1 ≥ 90%, ниже — код выхода 1. Сроки гейта не имеют, ниже 90% — предупреждение.

`pnpm eval:parser [--no-escalate] [--filter <префикс>] [--limit N] [--base <файл>]` читает `.env.local` и без `ANTHROPIC_API_KEY` не стартует. Модели — `PARSER_MODEL` и `PARSER_ESCALATION_MODEL`, по умолчанию `claude-haiku-4-5` и `claude-sonnet-5`. Прогон пишет файл в `tests/ai/results/` и печатает, что сломалось и починилось против прошлого; результат прикладывается к работе (CLAUDE.md, регламент 5).

Модель и «Правила компании» (D-138) проверяет тот же скоринг во вкладке «Лаб → Парсер»: корпус кусками на настройках компании, без случаев выключенных видов, куски подписывает сервер (`lib/ai/evals/stamp.ts`); правила сохраняются, только если прогон полный и проходит гейты.

`pnpm eval:harvest` выгружает подтверждённые разборы из `ai_logs` в черновики вне git и печатает долю правок директора по дням (D-35); в корпус черновик переносят руками.

## 5. Телефоны

Эмуляция не заменяет телефона для микрофона, пушей, главного экрана и вибрации. Устройства — iPhone 16–18 и Android-флагман (D-136); своего парка нет (D-26). Перед показом и после изменений в этих местах:

- голосовое с Android играет на iPhone, и наоборот;
- пуш доходит на заблокированный телефон (на iPhone — у приложения с главного экрана);
- пять минут в фоне, тем временем создана задача — после возврата лента актуальна;
- «Принял» без сети доходит после её появления один раз;
- тап по пушу при выгруженном приложении открывает задачу за 2–3 секунды;
- обрыв сети после записи: фраза ждёт на телефоне (`lib/voice/kept.ts`) и уходит сама.

Красный пункт — показ переносится.

## 6. Definition of Done

1. Экран проверен в эмуляции iPhone 16-класса и Android-флагмана (D-136); аудио — на живых телефонах: запись на Android, воспроизведение на iPhone.
2. Новая таблица, политика, бакет, RPC закрыты негативным pgTAP: сотрудник не видит чужого, компания — чужой компании (§2).
3. После пяти минут в фоне данные актуальны без перезагрузки.
4. Действие без сети доходит ровно один раз (`client_request_id`); голосовое сохраняется до вызова AI.
5. Сбой сети или AI оставляет понятное состояние: STT упал — аудио сохранено и есть «повторить» (`components/voice/IngestOverlay.tsx`), парсер упал — виден текст.
6. Логика из §3 — с unit-тестом, промпт и схема — с evals (§4), несовместимость — с `COMPAT`.
7. Запись в WORKLOG.md, conventional commit.

## 7. Перед выкаткой

Push в `main` выкатывает изменение всем компаниям, и проверок за разработчика никто не запустит (SETUP.md §1). Перед ним: типы, линт и unit; миграция уже в базе, pgTAP прогнан; с парсером — evals выше гейтов; смоуки затронутых экранов; для голоса, пушей и офлайна — телефоны. Новая компания перед первыми людьми — по SETUP.md §5.

## Не построено

- CI (D-19).
- «Компания A не видит компанию B» по каждой таблице, бакету и RPC (D-134 п. 6).
- Тестовый парк телефонов (D-26).

## Известные ограничения

- Браузерные смоуки, кроме `smoke:desk`, останавливаются на входе (§1).
- `pnpm eval:parser` гоняет модель по умолчанию; модель компании проверяет только «Лаб → Парсер».
