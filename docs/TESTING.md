# TESTING.md — тесты, гейты, Definition of Done

Что это: контракт по качеству продукта Pulse — тесты, гейты, Definition of Done; для агента, сдающего фичи. Арбитр — `DECISIONS.md`. Схема и seed — `docs/DATABASE.md`; среды и смоук деплоя — `docs/SETUP.md`; выбор STT-провайдера (этап 0) — `docs/STT_GATE.md`. Метки: `[есть]`, `[не построено]`.

## 1. Пирамида и команды

| Уровень | Команда | Что покрывает | Когда гоняется |
|---|---|---|---|
| Unit (Vitest) | `pnpm test` (`vitest run`) | matchName, время, обвязка парсера, ингест голосового (§3) | каждый коммит |
| RLS (pgTAP) | `pnpm test:rls` → `supabase test db --linked` | политики и RPC-инварианты (§2) | каждый PR с миграцией; требует Docker Desktop |
| Evals парсера | `pnpm eval:parser` | точность извлечения сущностей (§4) | каждый PR, трогающий промпт/схему/few-shot |
| СТТ-гейт | `pnpm test:stt` (`node tests/stt/run.mjs`) | корпус 50 фраз, метрики STT_GATE.md §4 | этап 0 (UI стартовал до его закрытия — D-47); повторно при смене STT-провайдера/микрофона |
| Смоук-скрипты `[есть]` | `pnpm smoke:*` (§1.1) | сквозные сценарии на dev: API, RLS, realtime, UI в браузере | руками, по затронутой фиче; перед демо |
| Девайс-смоук | вручную по чек-листу §5 | сквозной флоу на реальных устройствах | перед каждым демо/релизом в prod |

**CI нет** (`.github/` нет, `[не построено]`): все уровни гоняются руками, результат — в WORKLOG и в PR. Принцип: вниз пирамиды — всё детерминированное; AI-качество меряется evals, не unit-тестами.

## 3. Unit-критичное (Vitest, `pnpm test`)

Обязательные сьюты; фикстуры — на русском, реальные паттерны:

- **`matchName`** (`lib/matchName.ts`, `lib/matchName.test.ts`): падежи и уменьшительные («Марату», «Айгуль», «Ерлану Б.»); коллизия «два Ерлана» из seed → возврат кандидатов, не авто-выбор; пороги и отрыв (D-16) читаются из конфига — тест фиксирует поведение на граничных score; 0 кандидатов → «не распознан», никогда «наугад».
- **Время:** перевод ISO Asia/Aqtobe → UTC, дни недели и «Ближайшие дни» для промпта (`lib/ai/time.test.ts`). Конвенции «до обеда», «к вечеру» (D-15) — данные `company.settings.conventions`, срок по ним считает модель; детерминированный резолвер удалён. Unit проверяет только отрисовку таблицы в промпт (`lib/ai/conventions.test.ts`); точность сроков меряют evals (§4, метрика дедлайна).
- **Баланс, hold и статусы — уровень БД, не unit:** матрицу `trg_task_status_guard`, ролевые ограничения закрытия и отзыва, начисление очков проверяет pgTAP (§2: `003`, `007`, `008`, `009`). Hold-final магазина (заказ → −price, отмена → +price по `order_id`, выдача → ноль новых транзакций) тестами не покрыт — `[не построено]`.
- **Идемпотентность**: повтор мутации с тем же `client_request_id` не создаёт дублей и возвращает тот же результат (unit — один `client_request_id` на весь ингест, `lib/store/ingest.test.ts`; сквозное — pgTAP `006`, `007`, `018`).

## 4. Evals парсера (`pnpm eval:parser`, `tests/ai/parser_evals.jsonl`)

Формат фикстуры — JSONL, по строке на кейс (полное описание, состав серий и последний прогон — AI.md §6):

```json
{"id":"fs-03","source":"voice","transcript":"марат кп казхром завтра до обеда, ерлану б +10",
 "frozen_now":"2026-08-13T16:32:00+05:00",
 "expected":{"entities":[{"kind":"task","assignee_id":"u-003","deadline_iso":"2026-08-14T13:00:00+05:00"},
                          {"kind":"points","assignee_id":"u-001","amount":10}]}}
```

`frozen_now` обязателен — относительные даты сравниваются детерминированно. `assignee_id` — id демо-ростера `tests/stt/roster.json`. Скоринг: точность адресата (доля сущностей с верным `assignee_id` после matchName) и entity F1 (по `kind` + `assignee_id`), дедлайн ±30 мин. Отчёт пишется в `tests/ai/results/` и прикладывается к PR.

**Гейты: assignee ≥ 97%, entity F1 ≥ 90%.** Правило из CLAUDE.md: **PR, трогающий промпт парсера, схему сущностей или few-shot, без приложенного результата `pnpm eval:parser` не мержится.** Ниже гейта — PR не мержится, даже если «на глаз стало лучше». Корпус пополняется из реальных правок директора: `pnpm eval:harvest` выгружает подтверждённые разборы из `ai_logs` в черновики фикстур и печатает долю правок по дням (D-35) — каждая систематическая ошибка становится фикстурой до фикса промпта.

## 5. Девайс-смоук перед каждым демо (реальные устройства, не эмулятор)

Устройства: бюджетный Android (Redmi-класс) + iPhone (D-26). Чек-лист:

- [ ] **Аудио кросс-платформенно:** запись голосового на Android → воспроизведение на iPhone (и обратно); формат по матрице mimeType (audio/mp4 первым, G.8).
- [ ] **Push на MIUI:** уведомление доходит на Xiaomi/Redmi при выключенной оптимизации батареи (шаг онбординга, H.14); телефон заблокирован ≥5 минут.
- [ ] **Свернул/развернул:** приложение в фоне 5 минут, за это время создана задача → развернул → лента актуальна без перезагрузки (realtime + refetch).
- [ ] **Оффлайн:** самолётный режим → «Принял» на карточке → сеть → действие доезжает ровно один раз (идемпотентность, дублей в БД нет).
- [ ] **Cold start по пушу:** тап по push при убитом приложении → интерактивная карточка задачи < 2–3 с на Redmi-классе.
- [ ] **Голосовое не теряется:** обрыв сети сразу после записи → аудио в Storage, ретрай транскрипции без перезаписи.

Любой красный пункт — демо не проводим, чиним.

## 6. Definition of Done фичи

Фича готова, когда всё ниже выполнено (расширение краткой версии из CLAUDE.md):

1. **Мобильный смоук на двух платформах:** визуально проверено в эмуляции iPhone SE и среднего Android; фичи с аудио — реальный кросс-девайс смоук «Android-запись → iPhone-воспроизведение» (§5).
2. **RLS — негативный тест:** для каждой новой таблицы/политики есть pgTAP-кейс «чужое не видно / запретный insert падает» (§2), прогнан, зелёный.
3. **Realtime без перезагрузки:** свернул на 5 минут → развернул → данные актуальны; изменение в БД видно на открытом экране без F5.
4. **Оффлайн не теряет:** действие без сети доезжает после появления сети ровно один раз (`client_request_id`); голосовое сохранено в Storage до любых AI-вызовов при любом сбое.
5. **Ошибки сети/AI обработаны:** STT упал → ответ `stt_failed` «Не расслышал. Распознаю позже» (`app/api/voice/transcribe/route.ts`; на экране ингеста — «Не расслышал. Аудио сохранил — повторить?», `components/voice/IngestOverlay.tsx`) с ретраем по сохранённому аудио; парсер упал → сырой транскрипт с «Повторить»; у пользователя всегда понятное состояние, вызов залогирован в ai_logs.
6. **Тесты по слоям:** затронута критичная логика §3 → unit-тесты; промпт/схема/few-shot → evals с приложенным результатом (§4).
7. **Учёт:** запись в WORKLOG.md, conventional commit.
8. **Прошлая сборка не сломана молча:** изменение, с которым прошлая сборка не сможет работать (тело роута, аргументы RPC, форма читаемой таблицы, формат офлайн-очереди без чтения прежнего), поднимает `COMPAT` в `lib/version.ts` — телефоны получат экран «Нужно обновиться» (D-115).

## 7. Регрессия: раскатка на всю компанию (этап масштаба) и каждый новый клиент (V-02)

**Перед раскаткой на всю компанию (этап масштаба):** полный прогон `pnpm test` + `pnpm test:rls` + `pnpm eval:parser` (гейты §4) → девайс-смоук §5 на обоих устройствах → замер доставляемости push на ≥5 реальных телефонах сотрудников (H.14; Huawei без GMS → Telegram-канал, `[не построено]`) → проверка эскалации Telegram (push проигнорирован → дубль через таймаут; `[не построено]`, D-21, D-32) → бэкап prod и подтверждённая процедура восстановления (SETUP.md §7).

**Перед передачей каждого нового инстанса клиенту (V-02):** это часть чек-листа приёмки инстанса (SETUP.md §5): pgTAP-сьют прогнан **на самом инстансе** (не «на dev было зелёно»), смоук-чек-лист деплоя SETUP.md §3 (шаг 9) пройден на устройстве, версия миграций = HEAD `main`, `company.settings` соответствует анкете. Инстанс без зелёной регрессии клиенту не передаётся.
