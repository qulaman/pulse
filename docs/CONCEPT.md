# WAG Pulse — голосовое управление компанией

> Рабочее название. Внутренняя платформа для West Arlan Group: директор управляет компанией голосом, сотрудники получают поручения в PWA, всё происходящее видно в реальном времени на дашборде и ТВ-экране в кабинете.

---

## 1. Идея одним абзацем

Директор не печатает и не тыкает формы — он **говорит**, как говорил бы утром в кабинете. Система (Whisper → Claude) превращает его голосовые в структурированные задачи, объявления и начисления очков, показывает на подтверждение и разносит адресатам. Сотрудники работают в PWA-ленте «как в мессенджере с директором»: принимают задачи, отчитываются текстом/фото/голосом. Каждое действие — событие: из них собираются дашборд «Пульс», рейтинг сотрудников, магазин мерча за очки и живой ТВ-экран в кабинете директора, которым директор управляет с телефона как пультом.

**Ключевой принцип UX:** ценность = количество действий директора, которые мы убрали. Два равноправных входа: голос (зажал FAB) и свободный текст одной строкой (тап по FAB — для встреч и мест, где нельзя говорить; плюс Web Share Target — пересылка текста из любого приложения в парсер). Сотрудник имеет максимум 3 кнопки на карточке.

**Профиль директора:** миллениал, 37 лет, насмотренный пользователь (эталон — Kaspi/Telegram). Это поднимает планку полировки, но НЕ означает усложнения: простота ядра — верховный закон, глубина только вторым слоем. Конкурент продукта — не бумага, а его текущий workflow в Telegram; выигрываем скоростью (голосовое → карточка < 3 сек) и тем, что одно сообщение = пять разлетевшихся задач с видимыми статусами.

**Game feel:** приложение ощущается как крутая игра — отправка задачи «стрелой» летит в аватарку сотрудника, очки сыплются золотыми частицами, streak горит живым огоньком, обмен в магазине — лут-дроп с конфетти, ранги за пороги очков. Каталог эффектов и три железных правила (эффект не блокирует действие; полная версия только в ключевые моменты; бюджет производительности) — в docs/FRONTEND.md.

## 2. Роли

| Роль | Описание |
|---|---|
| `director` | Админ. Голосовой ввод, приёмка, очки, реакции, пульт ТВ, настройки |
| `manager` | Средний менеджмент: может получать задачу «распредели между своими» и создавать подзадачи своей группе |
| `employee` | Получает задачи, отчитывается, копит очки, тратит в магазине |
| `shopkeeper` | Завхоз магазина: подтверждает и выдаёт заказы мерча (может совмещаться с employee) |

## 3. Пространства приложения

### 3.1 Эфир (общая лента)
- Утренние голосовые объявления директора: аудио + транскрипт.
- Кнопка «Принял к сведению» — директор видит, кто прочитал.
- Публичные события: выдача мерча («🎁 Ерлан обменял 200 очков на худи»), похвалы.
- Вкладка «Рейтинг»: топ сотрудников за неделю/месяц с динамикой ↑↓ (публичность настраивается: весь список или только топ-5).

### 3.2 Личные каналы (директор ↔ сотрудник)
- Лента диалога в стиле мессенджера. Задача = карточка-«сообщение от директора»: текст, дедлайн, приоритет, оригинальное аудио.
- Кнопки сотрудника: **Принял / Уточнить / Не могу (причина)**.
- Отчёты: текст, фото (акты, накладные, скрины), голосовые (транскрибируются).
- Задачу закрывает только директор (Принято / На доработку) — цифровая субординация.

### 3.3 Пульс (дашборд директора, mobile-first)
Сверху вниз:
1. **Статус-вердикт**: одна строка + цветовой фон (зелёный/жёлтый/красный). Кнопка «Послушать сводку» (TTS).
2. **«Требует вас»**: стопки На приёмке / Вопросы / Просрочки / Заявки магазина → режим свайпов (вправо — принято, влево — доработка + голосовой комментарий, вверх — принято + 🔥 + очки).
3. **Живая лента** событий (Realtime), долгий тап → реакция или голосовой ответ.
4. **Люди**: сетка с цветными точками загрузки (зелёный в срок / жёлтый близко к дедлайну / красный просрочка / серый свободен). Тап → профиль → кнопка микрофона «дать задачу».
5. **Цифры недели**: 3 больших числа с ↑↓ (% в срок, среднее время реакции, закрыто задач) + один bar chart.

### 3.4 Магазин
- Сетка товаров: фото, название, цена в очках, прогресс-бар «до худи осталось 40 очков».
- Флоу: заказ → заморозка очков → заявка завхозу → подтверждение → выдача → окончательное списание.
- Админ-страница ассортимента: товары, фото, цены, остатки.

### 3.5 ТВ-режим (`/tv`)
- Экран 16:9 в кабинете, только наблюдение, ноль интеракций.
- Слева ~60% — живая лента (последние 8–10 событий, вплытие + золотая подсветка 2 сек).
- Справа сверху — статус-вердикт + 3 числа дня; справа снизу — карусель по 15 сек: топ-5 рейтинга → загрузка людей → график недели → выдачи мерча.
- Ночной `location.reload()` в 04:00, реконнект Realtime, индикатор «оффлайн».
- **Пульт с телефона директора** (Realtime-канал `tv_control`): фокус на сотруднике, фокус на задаче, итоги недели, сравнение двух сотрудников, «Вернуть эфир», авто-возврат через 10 мин.
- Гостевой режим: без фамилий и цифр.

## 4. Голосовой конвейер (сердце продукта)

```
Аудио (зажал кнопку) → Whisper API (ru) → текст
→ Claude (Haiku): извлечение сущностей из ОДНОГО голосового:
   [объявление?] [задачи: исполнитель+суть+дедлайн+приоритет]
   [очки: кому/сколько/за что] [напоминание себе] [отложенная отправка]
   [повторяющееся правило] [делегирование группе]
→ Экран подтверждения директору («Я понял так: 📢 + ✅ Марату до 9:00 + ...»)
→ «Всё верно» → запись в БД → push адресатам
```

- Матчинг имён: справочник сотрудников с алиасами («Ерлан» → user_id), fuzzy match; при неоднозначности — 2–3 варианта на выбор тапом.
- Голосовые **вопросы** к системе («Что там по Казхрому?», «Чем занят Ерлан?», «Кто не отчитался?») — tool use / function calling по Supabase.
- Аудио всегда сохраняется рядом с транскриптом.

## 5. Очки, реакции, рейтинг

- Баланс = сумма транзакций `point_transactions` (append-only, ничего не перезаписывается).
- Ручные: тапом при приёмке (+5/+10/−5, настраиваемо) или голосом («Ерлану плюс десять за скорость»). Снятие — всегда с причиной.
- Авто-правила (вкл/выкл в настройках): в срок +3, досрочно +5, просрочка −5, принял за 10 мин +1.
- Реакции директора (👍🔥👏⚡🤔👎) — золотая обводка, push сотруднику; 🔥 может авто-давать +2.
- Серии (streak), доска почёта в Эфире и на ТВ.
- Перспектива: конвертация очков в премию (1 очко = N тг) — прозрачный KPI.

## 7. Дорожная карта

| Этап | Срок | Содержимое |
|---|---|---|
| **MVP** | 3 нед | Личные каналы, голосовой парсер (одна задача), Пульс, push, приёмка |
| **+1** | 1 нед | Эфир, мульти-сущности из одного голосового, голосовые вопросы к системе |
| **+2** | 1 нед | Очки, реакции, рейтинг, свайп-приёмка |
| **+3** | 1–2 нед | Магазин, ТВ-режим + пульт, шаблоны/повторы, отложенная отправка |
| **+4** | по факту | TTS-сводки, делегирование деревом, умные напоминания, режим планёрки |

Выкатывать «фишками по неделям» — удерживает вау-эффект. Через месяц: анализ логов голосовых директора → следующие функции из реальных паттернов.

## 8. Риски и принципы

- **Главный риск — адаптация, не технологии.** Метрика успеха — % поручений, проходящих через систему (а не «нравится»). Договорённость с директором: 30 дней ВСЕ поручения через систему, иначе дашборд врёт и умирает.
- **Гейт перед разработкой: тест STT на голосе директора.** 30 реальных фраз (казахские имена, смешанная речь, шум) → если точность имён < ~95%, менять STT-провайдера (Deepgram/кастомный словарь) до написания UI.
- **Автоматизационная слепота**: через месяц директор жмёт «Всё верно» не глядя. Подсвечивать низкий confidence матчинга; мониторить долю правок в ai_logs — ноль правок = тревога, не успех.
- **Push хрупок** (iOS-ограничения, китайские Android убивают service worker): Telegram-fallback обязателен с первого дня + индикатор недоставки у директора («Марат не получил» ≠ «Марат игнорирует»).
- **Отказ AI-API**: деградационный режим — аудио сохранено, «распознаю позже», ручное создание задачи из 3 полей как аварийный путь; второй STT-провайдер в конфиге.
- **Социальные эффекты очков**: отпуск/больничный замораживает streak, а не сбрасывает; защита от фарминга авто-правил; штрафы не конвертируются в депремирование (трудовое право РК) — вниз очки на премию не влияют; канал возражения по начислениям.
- **Не спроектировано, добавить в бэклог**: отзыв/правка задачи после отправки (голосом), задача на нескольких исполнителей, роль заместителя на отпуск, оффбординг сотрудника (задачи/история/очки), лимит «Требует вас» (при 30+ — группировка, иначе уведомительная усталость).
- **Безопасность**: биометрия на вход директора, короткий TTL сессий, «разлогинить все устройства»; согласия сотрудников на обработку ПД и публичный рейтинг (закон РК о ПД); гостевой режим ТВ по умолчанию при фокус-режимах с ПД.
- **Если директор хоть раз правит распознавание руками системно — бросит.** Вкладываться в промпт парсера и алиасы имён.
- Статусов мало (6), кнопок у сотрудника — 3. Любое усложнение убивает адаптацию.
- Push на iOS: PWA обязана быть добавлена на главный экран (провести онбординг), fallback — Telegram.
- Экономика очков: калибровочный месяц; ~100–150 очков/мес при нормальной работе, худи ≈ 200. Цены и правила — редактируемые в админке.
- Публичный антирейтинг может демотивировать → настройка «топ-5 публично, остальное только директору».
- MVP запускать на 3–5 сотрудниках, не на всей компании.

## 9. Перспектива SaaS

Мультитенантность закладывать в схему с первого дня (`company_id` везде + RLS), по образцу системы для карьера. Ниша: «голосовое управление компанией для директоров старой школы» в Казахстане/СНГ. Демо-сцена продажи: «сотрудник зашёл — я нажал — его дела на стене». Доп-выручка: модуль мерча + партнёрство с типографией.
