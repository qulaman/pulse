# FRONTEND.md — PWA, экраны, дизайн-система, ТВ-режим

## Дизайн-принципы

- **Тёмная тема — основная и единственная в v1.** Дорогой, спокойный вид; статусные цвета горят на тёмном.
- Палитра: фон #0B0F14 → карточки #131A22; один акцент — фирменный цвет WAG; статусные green/yellow/red — ТОЛЬКО для состояний; золотой — только для реакций директора и подсветки нового на ТВ. Никакого цветного шума.
- Типографика крупная: ключевые числа Пульса — читаются на вытянутой руке. Кегль тела ≥16px.
- **Планка качества — уровень Kaspi/Telegram.** Директор — миллениал (37), насмотренный пользователь: лаги, дешёвые шрифты, отклик >100мс — заметит. Но насмотренность ≠ желание сложности: ядро остаётся максимально простым, глубина — только вторым слоем по явному тапу. Ни один экран не усложняется «авансом».
- **Game feel — часть продукта, не украшение.** Приложение должно ощущаться как крутая игра (эталон тактильности — Duolingo). Полный каталог эффектов — в разделе «Game Feel» ниже. Framer Motion для базовых переходов: вплытие событий, докрутка чисел (count-up), улёт карточек при свайпе. На ТВ — медленнее и плавнее, чем в телефоне.
- Хаптики (navigator.vibrate / iOS через тапы): подтверждение голосового, свайп-приёмка, удары «стрел», pull-to-refresh с фирменной анимацией.
- Скелетоны, не спиннеры. Экран появляется целиком за счёт одного агрегатного запроса.
- Русский язык UI. Тон — короткий, деловой, без канцелярита.

## PWA

- manifest + service worker (serwist/next-pwa): standalone, иконки, splash.
- Онбординг «Добавь на главный экран» (особенно iOS ≥16.4 — иначе нет push): пошаговый оверлей со скринами под платформу.
- Web Push: запрос разрешения не при первом входе, а после первого осмысленного действия (принял первую задачу) — конверсия выше.
- Оффлайн: кеш оболочки; очередь неотправленных сообщений/аудио в IndexedDB с авто-ретраем (стройплощадка = плохая связь).

## Экраны директора

### Кнопка ввода (глобальная, двухрежимная)
Плавающая FAB на всех экранах директора. **Зажал — голос**: запись (MediaRecorder, живая волна/пульсация вокруг кнопки — директор видит, что его слышат), отпустил — отправка. **Одиночный тап — текст**: поле свободного ввода «как написал бы в мессенджере» (телеграфный стиль ок, парсер разбирает), над клавиатурой — чипы частых исполнителей и пресеты дедлайнов. Оба входа ведут в один парсер и один экран подтверждения. Состояния: запись/ввод → «Распознаю…» (шиммер-скелетон карточек, которые «материализуются» в сущности) → подтверждение. При ошибке — «Не расслышал» + повтор (аудио не теряется).

**Тихий режим** (свитч в шторке): без звуков и TTS, для встреч. Входящие вопросы сотрудников в тихом режиме — быстрые ответы-чипы («Да», «Нет», «Позже», «Действуй сам») одним тапом.

**Web Share Target** (manifest, Android): «Поделиться» текстом из любого приложения (WhatsApp, почта) → WAG Pulse → текст уходит в парсер → экран подтверждения. Письмо заказчика превращается в задачу за два тапа.

### Экран подтверждения (/confirm)
Список распознанных сущностей карточками: 📢 объявление / ✅ задача (исполнитель-чип, дедлайн-чип, приоритет) / ➕ очки / 🔔 напоминание. Правки — только тапом: чип исполнителя → выбор из вариантов; чип дедлайна → быстрые пресеты (сегодня 18:00, завтра 9:00, завтра 13:00, своя дата); свайп сущности влево — удалить. Большая кнопка «Всё верно → Отправить». Автоотправка не делаем в v1.

### Пульс (/pulse) — блоки строго в порядке
1. Статус-вердикт: фон-градиент green/yellow/red, одна строка текста, кнопка 🔊 сводки (итерация 4+).
2. «Требует вас»: горизонтальные стопки-счётчики → тап открывает **режим свайпов**: карточка отчёта (фото крупно), вправо = Принято, влево = Доработка (открывает запись голосового комментария), вверх = Принято+🔥+очки. Прогресс «3 из 7» сверху.
3. Живая лента: Realtime insert в task_messages/announcements → элемент вплывает сверху. Долгий тап → шторка: реакции + «Ответить голосом».
4. Люди: grid аватарок, цветная точка (логика цвета из v_employee_load), бейдж числа активных задач. Тап → профиль сотрудника: задачи, метрики, история очков, FAB микрофона «дать задачу этому человеку» (передаёт assignee-контекст в парсер).
5. Цифры недели: 3 числа с ↑↓ к прошлой неделе + один bar chart (Recharts, кастомная тёмная стилизация, без легенд и сеток-мусора).

### Пульт ТВ
В профиле сотрудника и в карточке задачи — кнопка «📺 На экране» → POST /api/tv/control + хаптик + тост «На экране». Шторка пульта: Итоги недели / Сравнить двоих / Вернуть эфир.

## Экраны сотрудника

### Лента (/feed) — стиль мессенджера
Диалог с директором. Карточка задачи: заголовок, дедлайн-чип (красный при просрочке), приоритет, ▶️ плеер оригинального аудио + транскрипт под спойлером. Три кнопки: **Принял / Уточнить / Не могу**. «Не могу» — обязательное поле причины. Композер снизу: текст / 📷 фото / 🎤 голосовое (транскрибируется, отправляется аудио+текст).
Реакция директора на сообщение — эмодзи с золотой обводкой + push.

### Мои дела (/tasks)
Список активных по срочности, просроченные сверху красным. Тап → та же лента, отскролленная к задаче. Кнопка «Выполнено» на карточке → шторка «приложи результат» (фото/текст/голос) → pending_review.

### Профиль
Баланс очков крупно, место в рейтинге, streak («7 в срок подряд» с огоньком), история начислений с причинами, прогресс до выбранного товара из магазина.

## Game Feel — каталог эффектов

Единый слой `<EffectsLayer>` поверх всего приложения: через него летают все снаряды, частицы, цифры. Одна точка контроля производительности + глобальный выключатель (prefers-reduced-motion и настройка пользователя).

### Три железных правила
1. **Эффект никогда не блокирует действие.** Данные уходят в БД мгновенно по тапу; анимация играет после, поверх. Тапнул и свернул приложение — действие всё равно выполнено. Спектакль — слой поверх логики, не часть её.
2. **Полная версия — только в ключевые моменты.** При серийных действиях (разбор 10 отчётов подряд) — укороченные версии 200–300мс. Большой праздник — редко, микрофидбек — постоянно.
3. **Бюджет производительности.** Частицы — canvas (лёгкий эмиттер/tsParticles), не DOM; Lottie для сложного (огонь, конфетти) — файлы 20–50КБ; остальное — Framer Motion строго на transform/opacity. Обязательный тест на бюджетном Android (Redmi-класс): эффект на 8 fps хуже его отсутствия.

### Эффекты
- **Отправка задачи («стрела»)**: кнопка сжимается → карточка сворачивается в снаряд в стиле WAG → летит по дуге к аватарке исполнителя → удар: вздрагивание аватарки, вспышка, кольцо ударной волны, хаптик. Несколько задач — веер стрел с интервалом 100мс. Длительность полной версии 700–900мс.
- **Получение задачи (сотрудник)**: карточка «вонзается» в ленту сверху + screen shake 2–3px + хаптик.
- **Очки**: начисление — золотые цифры с частицами летят в счётчик баланса, счётчик докручивается с bounce; снятие — красные цифры падают вниз, глухой хаптик. Разная физика = разная эмоция.
- **Реакция директора**: эмодзи падает сверху на сообщение, при ударе — искры; золотая обводка разгорается, а не появляется.
- **Свайп-приёмка**: колода (верхняя карта приподнята с тенью); вправо — улёт с зелёным шлейфом; вверх с 🔥 — сгорает в частицах. Комбо-счётчик «Разобрано N подряд».
- **Streak**: живой огонёк (Lottie); продление — вспышка; потеря — гаснет с дымком.
- **Магазин**: обмен = «лут-дроп»: карточка переворачивается, вспышка, конфетти.
- **Ранги** (пороги очков: названия в стиле WAG): повышение — полноэкранная анимация. Ранги — надстройка над существующими point_transactions, отдельная таблица не нужна (вычисляются от суммы за период, конфиг в company.settings).
- **ТВ-экран**: события «выполнено досрочно» и начисления прилетают той же стрелой с ударом — публичный game feel на стене кабинета.

## Эфир (/ether)
Лента объявлений: карточка = аудио-плеер + транскрипт + счётчик «Приняли к сведению 34/42» (директору — список). Кнопка «Принял к сведению» у сотрудника. События мерча. Вкладка «Рейтинг»: топ с динамикой ↑↓ (учитывать настройку публичности top5/full).

## Магазин (/shop)
Grid карточек: фото, цена в очках, прогресс-бар до цели при нехватке. «Обменять» активна при достатке баланса. Мои заказы со статусами. Админ-страница ассортимента для director/shopkeeper (форма с загрузкой фото в Storage).

## ТВ-режим (/tv)

- Отдельный layout без навигации, 16:9, `cursor: none`, автозапуск: `chrome --kiosk`.
- Зоны: слева 60% лента (8–10 событий, новое — вплытие + золотая подсветка 2 сек, авто-вытеснение старых); справа сверху — вердикт + 3 числа дня; справа снизу — карусель 15 сек (топ-5 рейтинга → загрузка людей → график недели → выдачи мерча) с плавным кроссфейдом.
- Подписка на `tv_control:{company_id}`: режимы employee_focus (фото, имя, рейтинг, очки, задачи с пульсацией просрочек, график динамики, мелкая лента), task_focus (лента задачи, фото отчётов крупно), week_summary (рейтинг + лучший сотрудник крупно 🔥), compare (двое рядом). Переход между режимами — фирменная анимация (лого WAG → перестроение). Авто-возврат в эфир через 10 мин.
- Надёжность 24/7: `location.reload()` в 04:00; heartbeat Realtime → при обрыве реконнект + бейдж «оффлайн» в углу; все анимации через transform/opacity (без утечек layout).
- Гостевой режим (query `?guest=1`): без фамилий (имя + инициал), без цифр очков.

## Компонентная база

`<VoiceButton>` (запись+волна), `<TaskCard>` (варианты director/employee/tv), `<EventItem>`, `<StatusChip>`, `<PointsBadge>`, `<SwipeDeck>` (приёмка), `<AudioPlayer>` (волна+скорость ×1.5), `<CountUpNumber>`, `<RatingList>`, `<EmployeeDot>`. Всё в /components, Storybook не нужен — но каждому компоненту страница-песочница в /app/dev (только dev-режим).

## Производительность

- Пульс = 1 запрос mv_pulse_summary + 1 подписка Realtime. Никаких водопадов запросов по блокам.
- Изображения через next/image, фото-отчёты — превью из Storage transform (width=400), полноразмер по тапу.
- Аудио: opus/webm, битрейт ~24kbps — голос, не музыка; быстрая загрузка на плохой связи.
- Анимации: только transform/opacity (никаких width/height/top). Длительности: микрофидбек 100–150мс, переходы экранов ≤150мс (мгновенность важнее красоты у сотрудника), эффекты Game Feel 200–900мс по каталогу, ТВ 400–600мс. AnimatePresence со списками — mode="popLayout". Уважать prefers-reduced-motion. Кнопки действий срабатывают мгновенно, эффект догоняет.
- Целевые метрики: холодный старт PWA < 2 сек, голосовое → экран подтверждения < 3 сек. Конкурент — «написать в Telegram», выигрываем только скоростью.
